# Agent Note: 项目文档职责与权威来源

Status: implemented

## Problem

根目录的 `ARCHITECTURE.md`、`CLAUDE.md` 和 `PROGRESS.md` 曾同时承载当前架构、未来平台规划、开发命令、测试命令、项目指令、状态清单和验收标准。同一事实因此在多个文件重复出现，当前能力与未实现设计也没有稳定边界。仓库当时还缺少面向使用者的入口、固定的开发与测试权威文档、Agent Note 生命周期目录和文档字数预算，项目文档校验无法运行。

## Decision

项目采用分层文档体系，每类事实只有一个权威来源。项目文档和 Agent Note 正文使用中文；命令、路径、API 名称及 Agent Note 固定结构标题保留英文。

根目录的人类文档保留两个入口：

- `README.md` 面向使用者和新贡献者，简要说明项目定位、当前能力、安装与最短使用路径，并链接详细文档；
- `CLAUDE.md` 作为 Claude Code 自动加载的项目指令，只保留必须在每次会话中生效的仓库约束，并链接相应权威文档。

`docs/` 按职责组织：

- `docs/architecture.md` 只描述已实现系统的组成、运行流程、主要模块、边界和扩展点；
- `docs/subsystems/annotation-data.md` 负责标注值、几何、标签目录和格式 I/O 契约；
- `docs/subsystems/dataset-pipeline.md` 负责 `Source -> Pipeline -> Sink`、发现规则、转换语义和包级使用边界；
- `docs/subsystems/training-workflow.md` 负责 Scenario、数据集布局、训练、导出、预测检查和训练后端边界；
- `docs/development.md` 负责开发环境、安装、日常工作流、格式化、生成物和 Scenario 文件管理；
- `docs/testing.md` 负责测试层级、命令选择、fixtures、人工审核快照、静态检查及文档检查；
- `docs/agent-notes/` 按生命周期保存未来设计和已实施决策。

自助训练平台方向、P1 可行性证据、P2 至 P5 路线、待确认设计、验收标准和风险由 [内部自助训练平台](../../proposed/feature/2026-07-30-self-service-training-platform.md) 所有。未实现的平台结构不属于 `docs/architecture.md` 的当前事实。

`scripts/doc-budgets.manifest.json` 为全部受管 Markdown 文件设置正数字数上限。根目录旧架构和进度文档已经删除，仓库内引用指向新的事实所有者，不保留重复内容或兼容跳转页。

`.superpowers/` 保存本地 Superpowers 规格、计划和工作记录，由 Git 忽略，不属于项目文档体系，也不得进入文档预算或版本控制。

## Ownership rules

- 代码和测试是实现事实的最终依据；当前架构负责系统关系，子系统页面负责本地契约；
- 父文档完整描述自身主题，只概述直接子文档的目的和高层行为，并链接具体所有者；
- 当前状态表、手写导出目录和重复命令不在多个位置维护，入口文档只保留最短路径和链接；
- 当前状态使用现在时，未来设计只出现在 proposed Agent Note；已完成验证可以作为方案依据，但不写成作者工作过程；
- 每个事实保留行动者、条件、时序、否定保证、失败方式和后果，字数预算不能成为削弱契约的理由；
- 文档移动同时删除旧位置、添加新位置并修复全部仓库内入站引用；生成内容只通过其所有者和生成器修改。

## Alternatives considered

**维持三个根目录文档并只做文字精简。** 该方案文件数量少，但会继续让 `CLAUDE.md` 拥有开发和测试命令，让根目录架构页混合当前事实与未来规划，并保留手工进度清单，不能建立单一权威来源。

**使用紧凑的三份固定文档，不创建子系统文档。** 该方案会新增架构、开发和测试页，但标注、转换和训练契约仍会集中在架构页。现有三个代码子系统已经具有独立且稳定的公开概念，继续合并会使架构页承担直接子模块的实现级细节。

**保留旧路径作为跳转页。** 该方案可以兼容未发现的旧链接，但会让一次文档移动产生两个长期入口，并使读者无法仅凭目录判断事实所有权。仓库内引用可以在同一变更中修复，因此不保留跳转页。

## Consequences

读者可以从 README 进入项目，再按架构、子系统、开发、测试和 Agent Note 的职责定位事实。当前能力与未来提案不再混写，Claude Code 的自动入口也不再复制模块说明和命令目录。

该结构增加了文档文件数量，并要求跨文件变更主动更新 owning 页面和引用。删除旧路径可能影响仓库外书签；项目只保证仓库内引用完整，不维护永久重定向。字数预算提供漂移门禁，但编辑者仍需以契约完整性而不是最短篇幅为判断标准。

## Verification

项目文档校验检查受管文件存在、正数字数预算、单行段落、相对 Markdown 链接、标题片段和源码中的 `docs/*.md` 引用。Agent Note 校验检查生命周期、分类和固定结构；文档变更还运行推理过程泄漏扫描与 `git diff --check`。Python 源码、测试、fixtures 和生成物不因本决策改变。
