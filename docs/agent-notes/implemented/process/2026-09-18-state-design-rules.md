# Agent Note: 状态设计与权威事实规范

Status: implemented

## Problem

平台需要在刷新、重试、取消和服务重启后保持同一业务含义。把用户动作记录成业务阶段，再由多个入口推进或回退，容易让页面、数据库与外部服务各自维护不同答案。仅删除状态字段也不能解决问题：从远端执行结果猜测用户意图，同样会让恢复逻辑执行错误操作。

## Decision

本文是已生效的设计与审查规范，不代表所有代码自动符合。训练意图协调与新建 CVAT Task 准备已有离线实现和联合回归，[训练意图协调与 CVAT 准备简化](../simplification/2026-09-18-authoritative-state-coordination.md)记录具体机制及验收覆盖边界；[训练输入唯一性](../simplification/2026-09-17-training-input-identity.md)继续拥有运行身份与输入规则。

### Authority and derivation

- 每个事实必须明确唯一权威来源、写入者及读取方式；单一权威不要求所有数据集中在同一个数据库。标注数据库拥有标注事实，平台拥有用户意图与关联，执行服务拥有执行事实。
- 分开建模权威事实、用户期望、派生视图和临时过程变量。计数、按钮资格、可编辑性等可从事实得到的答案，每次从头判断，不从上次页面结果或持久业务阶段推进，不按用户动作维护加一、减一。
- 同一业务判断由同一规则提供给页面与写入校验；每次写入仍须重新校验，不能把上次页面显示当作授权。查询失败保留未知，不推断为不存在、已取消或已完成。
- 查询与执行协调分离。读取列表、详情和工作区不得隐含创建、入队、取消等业务副作用；状态刷新不是执行授权。
- 执行结束、取消请求、进程实际停止、产物完整及下载可用是不同事实，分别判断，不能用其中一个替代另一个。

### Recommended implementations

**从事实或产物重算。** 适用于数量、标注完整性、步骤门禁、缓存有效性和展示。读取权威记录及相关产物，校验身份、输入指纹和完整性，计算结果；不能只因目录存在就认定缓存可用。缓存只能加速查询，必须有明确的有效性条件，不能成为独立业务权威。需要一致读写时使用数据库事务、现有互斥或版本条件，不能把“重新查询”当作并发安全保证。

**期望状态与实际事实协调。** 适用于用户已授权但跨外部服务尚未完成的操作。先持久保存期望，再读取实际事实，只执行缩小差异所需的操作。期望取消不代表实际停止；期望执行也不授权重新启动终态任务。协调入口必须说明触发时机、重启后的接续方式、串行化或并发约束、重复执行语义以及无法确认时的处理。不能只改字段名称，内部仍按阶段推进。

两种方式可以组合：事实决定展示，期望决定允许采取的动作。没有跨请求恢复需求的短操作采用普通顺序调用或数据库事务即可，不必建立后台协调器。幂等写入、唯一约束和原子发布是保证重复执行安全的手段，不是另一套业务状态来源。

### Necessary records and limits

任务 ID、用户归属、输入指纹、对象映射、用户取消意图，以及无法从外部重建的请求 ID 或调用尝试事实可以持久保存。保存前必须说明该记录承载的事实，以及删除它会丢失什么；不能仅为“方便判断到第几步”新增字段。创建尝试记录只能证明尝试发生过，不能证明外部任务已创建。

外部副作用可能无法查询或不支持幂等。超时不证明失败，本地事务也不能保证远端恰好执行一次。此时允许保留必要操作证据并停止自动重试，报告需要核实的事实；不得为了形式上“无状态”而重复创建、覆盖人工标注或提前解锁。

函数内顺序执行、请求期间的 busy 提示、外部 API 返回的执行枚举都不属于被禁止的业务阶段副本。是否违反规范取决于它们是否取代权威事实，或决定跨请求恢复行为，而不是变量是否叫 state。

### Typical incorrect designs

| 错误设计 | 具体后果 | 正确约束 |
| --- | --- | --- |
| 上传后给有效图片计数加一，删除后减一 | 重试、去重和部分失败导致计数漂移 | 从已接纳的图片与标注事实重新统计 |
| 看到 ClearML `created` 就在查询时入队 | 已出队但取消尚未完成的任务被重新入队 | 读取不执行；协调必须同时检查用户意图与实际事实 |
| 调用取消成功就写“已停止”并解锁 | 请求被接受时 worker 可能仍在使用输入 | 取消意图与停止证据分别判断 |
| ClearML 已 `completed`，缺产物就认定仍在训练 | 产物缺失导致工作区持续锁定 | 执行结束与交付可用独立判断，不把缺产物称为成功交付 |
| 根据保存的 `initializing` / `initialized` 决定覆盖或读取 CVAT 标注 | 执行阶段取代对实际标注的核实，可能阻断恢复或重复初始化 | 无恢复需求时删除检查点接口；需要恢复时核实实际产物，歧义时不覆盖 |
| 页面和后端分别维护是否可编辑，提交与读取各有恢复分支 | 相同事实产生不同权限或不同外部动作 | 共用派生规则与执行协调入口 |

审查基线 `ade684d` 的 `TrainingService` 与 ClearML 适配器曾包含训练读取恢复、取消意图缺失及执行结束与产物耦合；当时的 CVAT 准备接口也混合实际图片核验与阶段检查点。当前实现按[训练意图协调与 CVAT 准备简化](../simplification/2026-09-18-authoritative-state-coordination.md)分离查询与协调、保存训练意图并删除未使用的 CVAT 阶段接口。该记录保留离线回归证据与真实验收覆盖边界；本规范只拥有通用设计规则。

### Review and verification

每个涉及状态的 spec 必须列出权威事实、用户期望、派生结果及各自所有者，说明为何必须持久保存每个新增字段。审查需回答：刷新或重启能否仅凭权威事实和必要意图重新得到答案；查询是否只读；同一动作重复调用是否造成额外副作用；未知是否被误当作否定；不同入口是否复用同一规则。

实现验证按实际风险覆盖重复请求、进程重启、外部调用成功但响应丢失、意图保存与副作用之间中断、取消与提交重叠、终态与缺失产物等情况。验证结果必须观察权威数据和实际外部调用，不能仅断言阶段字段到达期望值。不相关的故障场景不构成新增通用恢复框架的理由。

## Alternatives considered

**到处持久保存阶段状态机。** 易于描述执行顺序，但复制可推导结果并引入恢复路径。本项目默认不用。只有业务状态本身就是不可推导的权威事实，例如人工审批结论，且转换规则具有独立业务含义时，才另行论证有限状态机；不能用它包装执行步骤。

**完全不保存意图或操作证据。** 字段更少，却无法区分提交中断和取消中断，也无法安全处理外部结果不明。规范禁止派生状态副本，不禁止无法重建的事实。

**事件溯源。** 以不可变事件为唯一权威、从事件重放投影，适合必须保留完整历史的业务；它需要事件版本、重放和投影一致性设计。平台没有该需求，不为简化当前状态引入它。

**通用工作流引擎或事务发件箱。** 可支撑复杂长流程或可靠投递，但不能替代意图与事实的区分，也不能独自保证远端恰好执行一次。当前不引入；只有具体可靠投递需求无法由现有存储与小型协调入口满足时，才单独评估。

## Consequences

设计优先重算、必要时协调，普通操作保持顺序执行。代价是查询成本和外部不可用时的未知结果；如有性能证据，可以添加可验证的派生缓存，而不是另立业务权威。本规范不授权新增事件系统、调度器或迁移运行数据。

现有训练提案保留其产品与部署约束；本文替代其中“认证读取恢复入队”的设计许可。训练查询保持只读，持久意图由命令和应用生命周期协调。运行行为的离线证据与真实服务验收差距由具体修正提案承担。

具体修正范围由[训练意图协调与 CVAT 准备简化](../simplification/2026-09-18-authoritative-state-coordination.md)所有；本文不复制协调周期、持久字段或迁移细节。
