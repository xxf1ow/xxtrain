# Agent Note: 平台部署与数据集存储

Status: proposed

## Problem

内部人员需要使用共享基础训练样本和现场新增样本完成训练。现有图片、标注读取和训练转换已能支持本地使用；平台需要让用户自助推进流程，并让多台 GPU 机器承担训练，不应在缺少业务需求时另建数据格式、索引或版本系统。

## Proposal

平台采用一台 Ubuntu 主机和多台同局域网、长期在线的 Ubuntu 训练从机。主机保存数据，通过 NFS 向从机提供只读访问。数据沿用现有图片和标注文件，业务任务分别组织目录；Point 是一个业务任务，检测、分类、分割是其训练目标，用户选择业务任务及本次训练目标，每次只训练一个模型。

本文拥有部署、数据组织和上传去重方向；[平台总体提案](2026-07-30-self-service-training-platform.md)拥有用户流程、任务门禁和交付路线。预置 Point 现场的检测标注集成已经交付；上传、训练和 NFS 部署仍属于后续工作。下一步从自助页面的最小使用流程识别实际缺口，不将统一内部格式或数据库索引作为先行开发阶段。

## Deployment and storage

主机运行自建页面及后端、CVAT、ClearML Server，保存图片、正式标注和模型产物，并提供 NFS 共享目录。主机可同时运行 ClearML Agent，但需为交互服务保留资源。

从机仅部署 ClearML Agent、训练运行环境和 NFS 挂载，不运行自建本地服务。共享输入只读，转换、裁剪、框架缓存和训练临时输出写入执行机器本地工作目录，结果通过 ClearML 回传。接入时需验证框架不会向只读输入目录写缓存。

公网入口、网盘备份和 NFS 加从机本地数据缓存是独立后置方向，不阻塞局域网主线。公网入口采用主机主动连接 VPS 的反向隧道，VPS 只承担 HTTPS 入口和转发，不长期保存数据集；带宽、流量及临时缓冲仍需评估。网盘仅用于备份，备份与恢复范围由该功能设计确定。可选本地数据缓存用于读取性能优化，不等同于训练必需的本地工作目录。

## Existing data and training

基准数据集是参与训练的基础样本库，按业务任务分别管理，不建设固定 benchmark 评测集。Point、knob、light 等不相干的业务任务独立组织图片与标注，允许重复存图以方便人工区分和备份，不要求跨业务任务物理去重。

平台数据根目录把基准、用户工作区和运行产物分开：`baseline/<task>/` 只保存该业务任务的全局基准图片及标注，`workspaces/<user>/<task>/` 只保存该用户接纳图片及同 stem LabelMe JSON，`runtime/<user>/<task>/` 保存可丢弃的 CVAT 和训练缓存。第一版配置只有一个默认用户和 Point 任务；目录语义保留用户和任务层级。基准库仅管理员可见，且基准维护与读取不属于上传和检测训练缓存增量。

Point 的检测、分类和分割共享原图和完整 LabelMe JSON，都使用第一步确认的检测框。检测转换时将框标签统一映射为 `Point`，分类按框裁剪并读取 `tl/tc/cl/cc` 原标签，分割读取检测框及分割标注；转换不改写源 JSON。标注可使用本地工具直接编辑；预置 Point 现场的检测标注已通过 CVAT 集成，上传与检测训练缓存是下一增量，训练和 NFS 部署仍属于后续工作，不增加导出编辑副本、变化监听或标注修订管理。

平台按目标隔离 CVAT 标注内容：页面只加载和保存当前目标的标注。某图片的检测标注改变时，平台静默删除该图分类和分割标注；分类标注改变时，平台静默删除该图分割标注。缺少下游字段自然阻止下游缓存和训练，不另存标注有效性或修订状态。图片存在不代表所有训练目标标注完整，各目标仍只使用满足门禁的样本。

现有数据格式及本地 Scenario、转换和训练入口继续使用，不强制数据先导入新的内部格式或登记 SQLite。不建设每业务任务一份 SQLite、文件增量索引、标注历史修订、基础库发布系统或不可变清单作为页面前置条件；也不以全量重建数据库索引替代这些机制。未来仅在用户归属、标注完成状态、训练关联等页面需求无法由现有文件表达时补充必要业务元数据，数据库选型和划分届时确定。

历史训练输入保留不构成独立数据版本平台的立项理由，也不是本次批准的运行目录改造。若具体用户流程需要历史输入重用，再检查现有生成目录的保留和引用方式；目录并存但图片仍链接可变源文件时，不能宣称输入已冻结。现有训练重建行为以[训练工作流](../../../subsystems/training-workflow.md)为准。

## Upload deduplication

上传页面仍不要求通用导入与索引系统。接纳后的文件使用内容 SHA-256 作为 stem，原始上传名称不保留；图片及同 stem LabelMe JSON 位于用户和业务任务共同确定的工作区。基准库独立按业务任务组织，运行缓存位于工作区外。

- 同一业务任务上传图片与该业务任务基准库按文件内容哈希严格匹配，命中时清理重复上传，不建立重复标注副本，也不覆盖基准标注。
- 同一现场上传图片之间按任务固定的相似度阈值去重，覆盖多次上传形成的现场图片集合；与基准库比较不使用相似度，也不扩展为跨现场扫描。
- 不同业务任务的同图是合法独立副本，不因另一业务任务已收录而阻止当前任务标注；Point 各训练目标共享业务任务去重范围。

上传先写入临时目录，去重完成后原子接纳图片；被严格重复或相似过滤的候选直接清理，不提供找回或用户阈值调整。清理上传候选不删除基准库原图或已有正式标注。缺少某训练目标信息时补充已有标注，操作入口和权限由页面流程明确。文件哈希无法识别重新编码后的同图，该限制不通过引入新存储格式解决。

相似度使用 OpenCV 的 DCT pHash：图片解码为灰度、缩放到固定尺寸、取低频 DCT 系数并编码为 64 位哈希；两个哈希的异或位数是汉明距离。项目的 `opencv-python` 不包含 `img_hash` 扩展，平台自行使用 `cv2.dct` 实现该固定算法，不新增 `opencv-contrib` 依赖。Point 的初始阈值为距离不大于 2，刻意只过滤近乎相同的画面。候选按完整 SHA-256 排序，既有工作区图片优先；每个候选仅与既有和此前接纳候选比较，命中则清理。实现不构造全量距离矩阵、不按目录遍历顺序选代表图，也不在用户页面选择阈值。未来任务模板可定义自己的固定阈值。

## Integration direction

自建页面及后端管理用户流程，调用现有数据读取、转换和训练能力。CVAT 提供标注步骤，ClearML 提供队列、执行、日志、指标和模型产物。训练数据通过 NFS 提供给 Agent；任务如何选择输入、记录配置和限制编辑，由最小用户流程确定，不预先依赖数据集版本服务。

## Alternatives considered

**统一内部格式、每任务 SQLite 和强制训练入口迁移作为前置阶段。** 现有图片与标注已经可以消费，尚无证据说明新格式或派生文件索引能解决当前缺口。未来页面也可以直接调用现有能力，元数据应由真实业务状态需求决定。

**标注修订、发布清单及每次训练独立输入副本。** 这些机制服务于历史输入恢复，不能作为整理、备份当前数据和执行训练的必需条件。先确定具体流程需要保留哪些信息，再决定是否调整现有运行目录，不建设通用版本平台。

**VPS 平台加本地数据服务及训练客户端。** 需要额外的跨公网接收、暂存清理和本地服务。局域网主机承载平台后，VPS 仅作为后置公网转发功能。

**各 GPU 机器维护基础库副本、对象存储或 ClearML Data。** 当前局域网部署可通过主机 NFS 读取数据，无需数据同步服务、文件 API 或版本分发系统。

**跨业务任务共用原图目录，或每个训练目标分别存图。** 前者不便人工区分和独立备份，后者使 Point 共享标注重复。业务任务之间独立组织，同业务任务的训练目标共享图片与 JSON。

**统一编辑所有目标标签，或为 CVAT 定制目标编辑模式。** 前者会让下游编辑界面暴露上游工具，后者不是 CVAT 原生能力且需要维护高成本 UI 定制。平台改为按目标加载与保存，并在上游变化时删除同图下游标签。

**高阈值感知哈希、全量聚类或用户选择保留图片。** 感知哈希不能判断训练价值；高阈值和无序聚类会误删只有局部状态差异的图片。Point 以距离不大于 2 的确定性单遍比较保守去重，用户通过上传更多不同现场图片提高多样性，而不通过恢复被过滤候选绕过规则。

## Acceptance criteria

- 自助平台最小流程的设计能够逐项说明现有能力与实际缺口，不以新格式、SQLite 索引或训练入口迁移为前置依赖。
- 主机及训练 Agent 通过只读 NFS 使用数据完成独立训练，输入不被从机修改；公网入口、备份和可选缓存未部署时，局域网闭环仍可运行。
- 不同业务任务独立组织数据，Point 各训练目标共享图片与 JSON；一次只启动用户选择的模型。
- 页面上传按业务任务基准库哈希匹配和现场图片相似度两种范围去重，清理不损害已有基准图片和标注。
- 标注能使用本地工具编辑；Point 检测转换不改写原始分类标签，缺少某目标标注不被解释为所有目标均可训练。

## Risks

- 主机是平台与数据单点；备份后置意味着主线早期没有网盘恢复能力。
- 不同业务任务重复存图占用额外空间；NFS 性能受主机磁盘、网络和并发访问影响，可选缓存应以真实瓶颈为依据。
- 相似度过滤可能丢弃有价值样本，哈希匹配也不能覆盖重新编码后的同图。
- 直接编辑文件与异步训练之间的输入稳定性需要在真实提交流程中明确；现有目录不能自动提供历史输入冻结保证。
- CVAT 与现有标注的格式映射需验证必要语义，已有 COCO 小规模验证不能证明全部 Point 标注无损往返。
