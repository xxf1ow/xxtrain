# Agent Note: 平台部署与数据集存储

Status: proposed

## Problem

内部人员需要使用共享基础训练样本和现场新增样本完成训练。现有图片、标注读取和训练转换已能支持本地使用；平台需要让用户自助推进流程，并让多台 GPU 机器承担训练。工作区需要能明确表达步骤和对象关联，但不应扩展为通用数据格式、索引或版本系统。

## Proposal

本文原有的 LabelMe 权威存储、直接文件编辑、暂不建设 SQLite 和整图清除下游约定，已由 [SQLite 权威标注存储设计](../../implemented/architecture/2026-09-16-sqlite-annotation-storage.md)部分替代。工作区当前以原图和 `annotations.db` 为权威，按稳定对象身份清除受影响下游；部署、目录按业务任务隔离、基准库与工作区分离、去重范围及后置功能继续由本文约束。SQLite 运行路径已经通过离线测试、同版本 CVAT 身份往返和真实上传、标注、缓存验收。

平台采用一台 Ubuntu 主机和多台同局域网、长期在线的 Ubuntu 训练从机。主机保存数据，通过 NFS 向从机提供只读访问。数据沿用现有图片和标注文件，业务任务分别组织目录；Point 是一个业务任务，检测、分类、分割是其训练目标，用户选择业务任务及本次训练目标，每次只训练一个模型。

本文拥有业务数据组织、主机与训练机的数据关系及上传去重方向；[实测优先的服务端部署](../architecture/2026-09-24-evidence-first-server-deployment.md)负责服务端运行形态、生命周期和现场验收路径，[平台总体提案](2026-07-30-self-service-training-platform.md)拥有用户流程、任务门禁和交付路线。预置 Point 现场的批量上传、检测标注和检测缓存生成已经交付；SQLite 权威存储与对象身份运行路径已经完成真实 CVAT 验收。[分类与指针分割闭环](../../implemented/feature/2026-09-16-point-classification-segmentation.md)已经交付，拥有裁剪编辑、运行映射和训练缓存复用规则，不改变本文的数据隔离约束。训练提交、只读缓存消费和产物交付已有离线实现；真实 ClearML/GPU 执行、NFS 部署和管理员数据治理仍属于后续工作。

## Deployment and storage

主机运行自建页面及后端、CVAT、ClearML Server，保存图片、正式标注和模型产物，并提供 NFS 共享目录。主机可同时运行 ClearML Agent，但需为交互服务保留资源。

从机仅部署 ClearML Agent、训练运行环境和 NFS 挂载，不运行自建本地服务。共享输入只读，转换、裁剪、框架缓存和训练临时输出写入执行机器本地工作目录，结果通过 ClearML 回传。接入时需验证框架不会向只读输入目录写缓存。

公网入口、网盘备份和 NFS 加从机本地数据缓存是独立后置方向，不阻塞局域网主线。公网入口采用主机主动连接 VPS 的反向隧道，VPS 只承担 HTTPS 入口和转发，不长期保存数据集；带宽、流量及临时缓冲仍需评估。网盘仅用于备份，备份与恢复范围由该功能设计确定。可选本地数据缓存用于读取性能优化，不等同于训练必需的本地工作目录。

## Existing data and training

基准数据集是参与训练的基础样本库，按业务任务分别管理，不建设固定 benchmark 评测集。Point、knob、light 等不相干的业务任务独立组织图片与标注，允许重复存图以方便人工区分和备份，不要求跨业务任务物理去重。

平台数据根目录把基准、用户工作区和运行产物分开：`baseline/<task>/` 保存该业务任务的全局基准图片及标注；`workspaces/<user>/<task>/` 保存该用户接纳的原图和 `annotations.db`；`runtime/<user>/<task>/` 保存可丢弃的 CVAT Job 引用、裁剪图片和训练缓存。第一版配置只有一个默认用户和 Point 任务；目录语义保留用户和任务层级。基准库仅管理员可见，且基准维护与读取不属于上传和检测训练缓存增量。

Point 的检测、分类和分割共享原图和 SQLite 标注记录。记录用 `step_key` 声明步骤并用 `parent_id` 关联第一步检测框；检测转换把 `Point/tl/tc/cl/cc` 五种框标签投影为一个检测类别，分类和分割使用显式子记录。训练缓存直接消费步骤 frame 投影和任务定义的编码回调，不回写权威 JSON，也不提供普通文件编辑器直接修改权威标注、变化监听或标注修订管理。

平台按目标隔离 CVAT 标注内容：页面只加载和保存当前目标的标注。稳定 UUID 和当前 Job 的 CVAT 原生 ID 定位普通修改；平台按任务依赖和目标对象关联清除受影响的分类、分割或后续检测记录，不清除同图未受影响对象。全量替换丢失原生身份时按旧对象删除、新对象新增处理，不做坐标猜测。缺少下游记录阻止对应缓存和训练，不另存标注有效性或修订状态。

现有本地 Scenario、转换和训练入口继续使用；工作区的三表 SQLite 只承担图片登记、标注和当前 CVAT 对象映射，不是通用内部格式或文件索引。平台不建设旧数据迁移、标注历史修订、基础库发布系统或不可变清单，也不持久化业务阶段、标注有效性和页面计数。新工作区从数据库恢复，真实存量数据保持不动。

历史训练输入保留不构成独立数据版本平台的立项理由，也不是本次批准的运行目录改造。若具体用户流程需要历史输入重用，再检查现有生成目录的保留和引用方式；目录并存但图片仍链接可变源文件时，不能宣称输入已冻结。现有训练重建行为以[训练工作流](../../../subsystems/training-workflow.md)为准。

## Upload deduplication

上传页面仍不要求通用导入与索引系统。接纳后的图片使用内容 SHA-256 作为身份，原始上传名称不保留；图片文件和 `annotations.db` 位于用户和业务任务共同确定的工作区。基准库独立按业务任务组织，运行缓存位于工作区外。

- 后续基准库接入时，同一业务任务上传图片与该业务任务基准库按文件内容哈希严格匹配，命中时清理重复上传，不建立重复标注副本，也不覆盖基准标注。
- 同一现场上传图片之间按任务固定的相似度阈值去重，覆盖多次上传形成的现场图片集合；与基准库比较不使用相似度，也不扩展为跨现场扫描。
- 不同业务任务的同图是合法独立副本，不因另一业务任务已收录而阻止当前任务标注；Point 各训练目标共享业务任务去重范围。

上传先写入临时目录，去重完成后原子接纳图片；被严格重复、相似过滤、扩展名不支持或无法解码的候选直接清理，不提供找回或用户阈值调整。当前 `WorkspaceData` 只比较工作区图片与本批较早接纳的候选，不读取基准库。清理上传候选不删除基准库原图或已有正式标注。缺少某训练目标信息时补充已有标注，操作入口和权限由页面流程明确。文件哈希无法识别重新编码后的同图，该限制不通过引入新存储格式解决。

相似度使用 OpenCV 的 DCT pHash：图片解码为灰度、缩放到固定尺寸、取低频 DCT 系数并编码为 64 位哈希；两个哈希的异或位数是汉明距离。项目的 `opencv-python` 不包含 `img_hash` 扩展，平台自行使用 `cv2.dct` 实现该固定算法，不新增 `opencv-contrib` 依赖。Point 的初始阈值为距离不大于 2，刻意只过滤近乎相同的画面。候选按完整 SHA-256 排序，既有工作区图片优先；每个候选仅与既有和此前接纳候选比较，命中则清理。实现不构造全量距离矩阵、不按目录遍历顺序选代表图，也不在用户页面选择阈值。未来任务模板可定义自己的固定阈值。

## Integration direction

[Point 自助训练与结果交付](../../implemented/feature/2026-09-17-point-training-loop.md)细化单 Agent 排队执行、缓存保留、Agent 本地写入目录和工作区解锁设计。真实 Agent/GPU 训练已验收，多机 NFS 部署仍待验收；本文的主机权威存储与只读 NFS 方向不变。

自建页面及后端管理用户流程，调用现有数据读取、转换和训练能力。CVAT 提供标注步骤，ClearML 提供队列、执行、日志、指标和模型产物。训练数据通过 NFS 提供给 Agent；任务如何选择输入、记录配置和限制编辑，由最小用户流程确定，不预先依赖数据集版本服务。

## Alternatives considered

**统一内部格式、通用文件索引和强制训练入口迁移。** 工作区采用 SQLite 是为了显式对象关系和原子更新，不要求 Scenario、基准库或训练入口迁入统一格式，也不把数据库扩展为目录镜像或数据版本平台。

**标注修订、发布清单及每次训练独立输入副本。** 这些机制服务于历史输入恢复，不能作为整理、备份当前数据和执行训练的必需条件。先确定具体流程需要保留哪些信息，再决定是否调整现有运行目录，不建设通用版本平台。

**VPS 平台加本地数据服务及训练客户端。** 需要额外的跨公网接收、暂存清理和本地服务。局域网主机承载平台后，VPS 仅作为后置公网转发功能。

**各 GPU 机器维护基础库副本、对象存储或 ClearML Data。** 当前局域网部署可通过主机 NFS 读取数据，无需数据同步服务、文件 API 或版本分发系统。

**跨业务任务共用原图目录，或每个训练目标分别存图。** 前者不便人工区分和独立备份，后者使 Point 共享标注重复。业务任务之间独立组织，同业务任务的训练目标共享原图和标注数据库。

**统一编辑所有目标标签，或为 CVAT 定制目标编辑模式。** 前者会让下游编辑界面暴露上游工具，后者不是 CVAT 原生能力且需要维护高成本 UI 定制。平台按目标加载和保存，并在上游对象变化时只清除受影响目标的下游记录。

**高阈值感知哈希、全量聚类或用户选择保留图片。** 感知哈希不能判断训练价值；高阈值和无序聚类会误删只有局部状态差异的图片。Point 以距离不大于 2 的确定性单遍比较保守去重，用户通过上传更多不同现场图片提高多样性，而不通过恢复被过滤候选绕过规则。

## Acceptance criteria

- 自助平台最小流程能够逐项说明现有能力与实际缺口；工作区 SQLite 不要求现有 Scenario、基准库或训练入口迁移。
- 主机及训练 Agent 通过只读 NFS 使用数据完成独立训练，输入不被从机修改；公网入口、备份和可选缓存未部署时，局域网闭环仍可运行。
- 不同业务任务独立组织数据，Point 各训练目标共享原图和标注数据库；一次只启动用户选择的模型。
- 页面上传按业务任务基准库哈希匹配和现场图片相似度两种范围去重，清理不损害已有基准图片和标注。
- 平台通过 CVAT 编辑数据库权威标注；Point 检测转换不改写原始分类标签，缺少某目标标注不被解释为所有目标均可训练。

## Risks

- 主机是平台与数据单点；备份后置意味着主线早期没有网盘恢复能力。
- 不同业务任务重复存图占用额外空间；NFS 性能受主机磁盘、网络和并发访问影响，可选缓存应以真实瓶颈为依据。
- 相似度过滤可能丢弃有价值样本，哈希匹配也不能覆盖重新编码后的同图。
- 数据库与原图文件不能原子提交，异步训练的输入稳定性仍需在真实提交流程中明确；现有目录不能自动提供历史输入冻结保证。
- CVAT 原生对象 ID 在常规编辑中稳定；复制产生新身份，全量替换按删除和新增处理，不能依靠坐标猜测保留旧身份。
