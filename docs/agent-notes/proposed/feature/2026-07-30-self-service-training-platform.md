# Agent Note: 内部自助训练平台

Status: proposed

## Problem

xxtrain 已能把外部标注转换为可训练数据集，并完成训练、预测检查和 ONNX 导出，但现场实施仍依赖管理员逐次整理图片、分发标注、执行命令和反馈进度。标注与训练执行分散在不同工具中，普通用户无法从一个受控入口独立完成固定垂类任务的训练，也没有由 xxtrain 掌握的工作区、权威数据和历史训练输入边界。

平台的目标不是减少一次训练所需的标注量，而是把数据准备、标注推进和训练执行从管理员的单点职责转移给现场实施人员。管理员只定义任务模板、低频维护基准数据并处理少量异常。

## Proposal

xxtrain 将在现有训练核心之外增加一个内部自助训练平台。普通用户通过 xxtrain 的统一入口选择开发者预定义的任务模板，在当前现场工作区上传图片、完成标注或审核、提交单模型训练、查看进度并取得模型。CVAT 提供标注画布，ClearML 提供训练排队和执行，xxtrain 保留业务流程、权威数据和跨平台状态的所有权。

P1 已用 4 张图片和单类别 `point-detect` 任务验证真实链路：CVAT Job 完成 4 个框后导出 COCO，xxtrain 转换为 3 张训练图片和 1 张验证图片，ClearML Agent 在真实 GPU 上完成一轮训练并保存 ONNX，产物可通过接口取回且通过 ONNX 结构校验。该结果证明组件组合可行，也表明 CVAT 的完成与返回路径、ClearML 的普通用户信息范围都需要由 xxtrain 包装。

第一版只供内部人员单机使用。平台入口、数据层和两个连接器是同一应用内的逻辑组件，不拆成微服务，也不增加消息队列、对象存储或通用工作流引擎。

## Product boundary

- 普通用户只能选择开发者定义的任务模板和训练预设，不能创建任务结构、修改标签定义或编辑底层训练参数；
- 每次训练运行只训练一个模型，多模型业务分别提交相应模板，平台不编排自动模型 DAG；
- xxtrain 是普通用户唯一入口，ClearML 只作为管理员后台，CVAT 只暴露当前标注步骤所需的最小界面；
- 不维护 CVAT 或 ClearML 的中文分支；xxtrain 负责标注入口、提交、状态同步、失败反馈和返回路径；
- 第一版不建设通用 AutoML、通用数据平台、完整 MLOps、商业多租户、复杂鉴权、计费、跨机器数据迁移或分布式训练；
- FiftyOne、ClearML Data 和 ClearML Pipeline 不进入第一版；自动清洗先服务普通上传路径，不提前建设通用数据探索平台；
- 管理员低频兜底和基准数据提升不能成为用户继续标注或训练的前置条件。

## Domain and data ownership

**任务模板**由开发者定义一个单模型业务规则，包括模型类型、标签定义、标注门禁和训练预设。**工作区**是某个用户在某个现场和任务模板下持续上传、标注和训练的可变数据范围。**正式标注**由人工创建，或由人工审核通过的模型候选转化而来；正式标注可以尚未完成，能否进入训练由任务门禁判断。**训练快照**在提交时冻结图片、完整标签、任务模板和可识别的训练代码版本。**训练运行**是 ClearML 基于一个快照排队和执行的一次单模型训练。

xxtrain 拥有任务模板、身份映射、工作区、正式标注、步骤门禁、训练快照和跨平台业务状态。SQLite 保存最小元数据和关系，文件系统保存按内容寻址的单份权威原图。工作区、基准数据和训练快照只引用原图；CVAT 缓存、训练数据物化目录和 ClearML 产物是可重建或可清理的工作副本，不能反向成为平台真值。CVAT 和 ClearML 的对象 ID 只用于映射与对账，不能充当平台业务身份。

用户数据的业务引用和查询范围按用户、任务模板和现场工作区隔离。底层文件可以跨工作区去重，但不得因此暴露其他工作区的数据。每个任务模板拥有一套对普通用户隐藏、跨用户共享的基准数据；只有管理员提升后的用户数据才跨工作区使用。该设计假设同一模板的数据允许跨用户进入共享基准；若实际权属不允许共享，必须重新设计客户级数据边界。

多次上传直接追加到当前工作区，不保留 `upload_batch_id`。用户移除、模糊过滤、相似度过滤和标注状态具有独立语义；移除或过滤只改变逻辑状态，不立即删除原图，也不能清除已有正式标注。未审核候选、审核进度、置信度、临时裁剪、缓存、日志和指标是过程产物，不进入长期权威数据。

## Annotation and training flow

下级任务模板依赖完整、合格的上级标签，不依赖上级训练运行、checkpoint 或执行历史。下级标注先取得并逐图确认全部上级标签，再标注当前模型目标；上级标签可以人工创建、从现有数据集导入或由已有模型生成候选，但模型候选必须人工审核。未完成当前目标标注的数据可以留在工作区，但不能进入训练，也不能解释为负样本。上级标签不合格时平台阻止下级训练，不自动启动其他模型补救。

Point 检测、分类和分割是三个独立模板，分类与分割都依赖完整可信的 Point 框。一个 Point 框只保存一次：`Point` 表示一级框已确认但分类未完成，`tl/tc/cl/cc` 表示已经具有二级分类。检测把五种标签投影为 `Point`，分类只使用四种子类。一级完成状态按整张原图确认，必须补漏并明确无目标图片；Point 框不得重叠，每个合法框都存在真实二级目标。分类和分割裁剪只在预览或训练时临时生成。

训练静默组合提交时的模板基准数据和当前工作区内未移除、未过滤且满足门禁的数据。提交后快照不可被后续上传、移除或标签修改改变。训练运行排队或执行期间禁止修改该工作区标签；运行中断或结束后才可修改，且修改只进入后续快照。ClearML 负责队列、执行、日志、指标和模型产物，普通用户只看到推进任务所需的状态、基本进度、失败信息和结果。

## Delivery stages

**P2：平台数据基础。** 建立 SQLite 元数据、内容寻址单份原图、隔离工作区、隐藏基准关系、独立逻辑状态和不可变训练快照，只提供验证这些边界所需的最小入口。该阶段不实现完整 UI、自动清洗算法、CVAT 页面集成、ClearML 用户进度页或管理员提升流程。

**P3：用户自助闭环。** 在稳定数据边界上打通上传清洗、标注审核、训练提交、进度反馈和模型获取，使用户不依赖管理员逐次推进。

**P4：基准数据积累。** 管理员按模板低频提升合格数据，提升只增加关系，不复制原图，也不阻塞用户任务。

**P5：按需扩展闲置算力。** 只有出现真实排队或算力需求时才增加 ClearML Agent；多台机器执行独立任务，不为单次训练建设跨机器分布式训练，也不改变平台数据所有权。

路线按依赖推进。P2 的内容标识算法、文件布局、SQLite schema、状态表示、事务恢复、快照清单和重试规则需要在阶段设计中明确，本文不预先指定表名、字段名、接口或参数。

## Alternatives considered

**建设通用 AutoML、数据平台或完整 MLOps。** 当前用户只需要固定垂类模板的受控闭环，通用工作流、参数编辑和实验分析会扩大权限、状态和支持成本，不能解决管理员单点瓶颈的核心问题。

**让用户直接在 CVAT 和 ClearML 原生页面间推进。** P1 证明两者能够执行专业步骤，但 CVAT 完成后不返回业务流程，ClearML 又暴露过多实验信息，无法共同承担普通用户的步骤门禁和失败反馈。

**把多级业务实现为自动模型 DAG。** 下级任务依赖的是经人工确认的上级标签，而不是某次上级模型执行；自动训练链会混淆标签门禁和模型运行历史。

**把未审核预测直接用于训练或采用半监督训练。** 检测漏检会把真实目标解释为背景，现场初始标签质量不足以支撑可靠自训练。除非独立现成方案先在真实数据上证明有效，否则不重新引入。

**第一版即建设微服务、多机调度或分布式训练。** 典型任务只有一两千张图片，单机和独立 Agent 已足够验证业务闭环；预建分布式控制面没有真实负载依据。

## Acceptance criteria

- 按最终内容标识判定为相同的图片重复上传时，物理文件只保存一份，同时允许建立多个合法业务引用；
- 不同用户和现场工作区的业务引用与查询相互隔离，共享底层文件或隐藏基准不会暴露其他工作区内容；
- 用户移除、过滤和标注状态可以独立变化，重启后保持一致；逻辑移除或过滤不删除原图和已有正式标注；
- 预置的隐藏基准数据能与当前工作区中满足门禁的数据组合为训练输入；
- 训练快照创建后不受后续上传、删除或标签修改影响，并能重建同一份训练输入；
- 训练运行排队或执行时不能修改该工作区标签，运行中断或结束后可以修改且只影响后续快照；
- 平台能识别快照引用的权威文件缺失或损坏；
- 导入或快照创建中途失败后，不留下指向不存在文件的有效业务记录；
- P3 完成后，普通用户能从 xxtrain 单一入口完成上传、标注、训练和模型获取；P4 与 P5 分别以基准提升和新增独立 Agent 不改变数据所有权为完成条件。

## Risks

- 内容寻址文件与 SQLite 关系涉及双写，写入顺序、失败状态和恢复机制若不明确会产生悬空记录或无主文件；
- 把多个逻辑状态压成单一枚举会让移除、过滤、标注和基准关系互相覆盖；
- 把可变目录当作快照会使历史训练输入不可解释，物化目录必须始终是可重建产物；
- 过早耦合 CVAT 或 ClearML 对象会让外部生命周期侵入平台身份；
- 当前跨用户共享基准的权属假设可能不适用于未来客户，确认不允许共享时必须先引入新的数据边界；
- 固定模板和单机范围放弃了通用扩展能力，但这是第一版保持简单、可靠且可验收的必要取舍。
