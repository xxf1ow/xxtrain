# Agent Note: 内部自助训练平台

Status: proposed

## Problem

xxtrain 已能把外部标注转换为可训练数据集，并完成训练、预测检查和 ONNX 导出，但现场实施仍依赖管理员逐次整理图片、分发标注、执行命令和反馈进度。标注与训练执行分散在不同工具中，普通用户无法从一个受控入口独立完成固定垂类任务的训练，也没有由 xxtrain 掌握的工作区、权威数据和历史训练输入边界。

平台的目标不是减少一次训练所需的标注量，而是把数据准备、标注推进和训练执行从管理员的单点职责转移给现场实施人员。管理员只定义任务模板、低频维护基准数据并处理少量异常。

## Proposal

xxtrain 将在现有训练核心之外增加一个内部自助训练平台。普通用户通过 xxtrain 的统一入口选择开发者预定义的业务任务和训练目标，在当前现场工作区上传图片、完成标注或审核、提交单模型训练、查看进度并取得模型。CVAT 提供标注画布，ClearML 提供训练排队和执行，xxtrain 保留业务流程、权威数据和跨平台状态的所有权。

P1 已用 4 张图片和单类别 `point-detect` 任务验证真实链路：CVAT Job 完成 4 个框后导出 COCO，xxtrain 转换为 3 张训练图片和 1 张验证图片，ClearML Agent 在真实 GPU 上完成一轮训练并保存 ONNX，产物可通过接口取回且通过 ONNX 结构校验。该结果证明组件组合可行，也表明 CVAT 的完成与返回路径、ClearML 的普通用户信息范围都需要由 xxtrain 包装。

第一版供内部人员在局域网使用，采用一台 Ubuntu 主机承载平台和权威数据、多台 Ubuntu ClearML Agent 执行独立训练的部署。平台入口、数据层和两个连接器是同一应用内的逻辑组件，不拆成微服务，也不增加独立消息队列、对象存储或通用工作流引擎。部署与数据格式由[平台部署与数据集存储](2026-09-14-platform-dataset-storage.md)所有。

## Product boundary

- 普通用户只能选择开发者定义的业务任务、训练目标和训练预设，不能创建任务结构、修改标签定义或编辑底层训练参数；
- 每次训练运行只训练所选业务任务中的一个模型，多模型业务由用户分别选择训练目标提交，平台不编排自动模型 DAG；
- xxtrain 是普通用户唯一入口，ClearML 只作为管理员后台，CVAT 只暴露当前标注步骤所需的最小界面；
- 不维护 CVAT 或 ClearML 的中文分支；xxtrain 负责标注入口、提交、状态同步、失败反馈和返回路径；
- 第一版不建设通用 AutoML、通用数据平台、完整 MLOps、商业多租户、复杂鉴权、计费或单次训练跨机器分布式执行；从机通过只读 NFS 访问主机数据，不维护权威数据同步服务；
- FiftyOne、ClearML Data 和 ClearML Pipeline 不进入第一版；自动清洗先服务普通上传路径，不提前建设通用数据探索平台；
- 沿用现有图片、标注格式和本地训练入口，不以前置统一格式、SQLite 文件索引或强制训练入口迁移支撑页面；
- 管理员低频兜底和基准数据提升不能成为用户继续标注或训练的前置条件。

## Component responsibilities

平台划分为六个逻辑模块，使每项业务规则和数据都有明确所有者，允许页面、标注与训练分别演进。页面可以是独立前端工程，其余模块可以是同一后端项目中的 Python 包；不要求六个服务、仓库或独立发布单元。物理包结构按实际实现确定，现有训练核心继续复用。

| 模块 | 负责 | 不负责 |
|---|---|---|
| 页面 | 接收用户操作，展示业务状态、校验错误和结果，提供标注与问题定位入口 | 判断训练资格、计算标注位置关系、直接操作文件或第三方 API |
| 平台业务流程 | 用户和现场工作区归属、任务与模型选择、步骤协调、业务状态及外部对象关联；依据规则校验结果控制训练提交 | 实现几何规则、解析 CVAT 格式、执行模型训练 |
| 数据管理 | 图片和 LabelMe 文件的读取与保存、上传去重和移除、基准库与现场数据的存储边界 | 判断业务标注合格性、管理 CVAT Job、提交训练 |
| 任务规则与训练核心 | 任务标签语义、训练目标要求、位置匹配和标注校验、数据转换、模型训练 | 用户会话、网页跳转、CVAT 和 ClearML 对象管理 |
| CVAT 适配 | 创建与分配标注任务、传入图片及已有标注、取回与格式映射、Job/帧定位、会话接入及薄前端插件 | 判断训练资格、直接改写基准库、启动训练 |
| ClearML 适配 | 提交排队、查询执行状态和日志、获取产物；Agent 执行入口调用现有训练核心 | 判断样本合格性、解释标注语义、管理用户工作区 |

主要调用关系如下，表示逻辑依赖，不要求模块间网络通信：

```text
页面 → 平台业务流程
          ├─ 数据管理
          ├─ 任务规则与训练核心
          ├─ CVAT 适配
          └─ ClearML 适配

ClearML Agent 执行入口 → 任务规则与训练核心
```

跨包只使用公开函数和类型，不访问私有实现、不直接修改其他模块拥有的文件或数据库表，不形成循环依赖。CVAT 和 ClearML SDK 对象停留在各自适配模块，业务流程与规则使用平台定义的数据。后端模块之间可以普通 Python 调用协作，不为隔离而增加 HTTP、通用插件框架或无实际需要的抽象类。

平台业务流程负责跨模块协调：CVAT 适配返回标注，数据管理保存现场文件，任务规则组件执行校验，页面展示错误和修正入口。CVAT 适配不直接调用数据管理或校验组件。插件只保存并返回，不执行 Point 业务规则；返回平台后的校验与训练前校验复用同一套规则。保存成功、CVAT Job 完成和允许训练是不同事实；业务校验失败时保留用户标注，允许返回对应 Job 和问题帧修正。

数据管理提供训练输入访问，平台业务流程确定输入范围与预设并检查训练资格，ClearML 适配负责交付执行。Agent 在本地工作目录调用现有核心进行转换和训练，不把算法逻辑写进提交接口，也不让 ClearML 成为数据集管理系统。六模块是职责约束，不是必须先全部搭建完成的空包目录。

## Domain and data ownership

**业务任务**是 Point、knob、light 等独立数据管理范围，由开发者通过任务模板定义共享标签和可选训练目标。**训练目标**定义一个模型的转换规则、标注门禁和训练预设；Point 检测、分类和分割是同一业务任务的三个目标。**工作区**是某个用户在某个现场和业务任务下持续上传、标注和训练的可变数据范围。**正式标注**由人工创建，或由人工审核通过的模型候选转化而来；能否进入训练由所选目标的门禁判断。**训练运行**是用户选择业务任务和训练目标后提交给 ClearML 排队和执行的一次单模型训练；输入与配置如何记录由具体提交流程确定。

xxtrain 拥有任务模板、工作区、正式标注、步骤门禁和跨平台业务流程。业务任务分别组织现有图片与标注目录，跨业务任务允许重复存储。是否需要数据库保存用户归属、标注完成状态和训练关联等信息，由最小页面流程决定，不预设每任务 SQLite。数据组织与部署由[数据存储提案](2026-09-14-platform-dataset-storage.md)所有。CVAT 和 ClearML 对象用于专业步骤与业务映射，不替代平台的业务任务定义。

用户数据的业务引用和查询范围按用户、业务任务和现场工作区隔离。文件组织不得暴露其他工作区的数据。每个业务任务拥有一套对普通用户隐藏、跨用户共享的基准数据，各训练目标按门禁选择合格样本；只有管理员提升后的用户数据才跨工作区使用。该设计假设同一业务任务的数据允许跨用户进入共享基准；若实际权属不允许共享，必须重新设计客户级数据边界。

基准数据是基础训练样本库，不建设固定评测集。同业务任务上传与基准库按文件哈希严格去重，同一现场上传图片之间按相似度阈值去重；命中基准库的重复上传不建立标注副本。已有图片缺少某训练目标标注时，通过编辑已有 JSON 补充，不因重复上传判定为标注齐全。现有 LabelMe 数据组织及清理范围见[数据存储提案](2026-09-14-platform-dataset-storage.md)。

多次上传直接追加到当前工作区，不保留 `upload_batch_id`。用户移除、模糊过滤、相似度过滤和标注状态具有独立语义；移除或过滤只改变逻辑状态，不立即删除原图，也不能清除已有正式标注。未审核候选、审核进度、置信度、临时裁剪、缓存、日志和指标是过程产物，不进入长期权威数据。

## Annotation and training flow

依赖上级标签的训练目标要求这些标签完整、合格，不依赖上级训练运行、checkpoint 或执行历史。下级标注先取得并逐图确认全部上级标签，再标注当前模型目标；上级标签可以人工创建、从现有数据集导入或由已有模型生成候选，但模型候选必须人工审核。未完成当前目标标注的数据可以留在工作区，但不能进入该目标训练，也不能解释为负样本。上级标签不合格时平台阻止下级训练，不自动启动其他模型补救。

Point 检测、分类和分割共享业务任务的图片与完整 LabelMe JSON，分类与分割都依赖完整可信的 Point 框。同一份标注中不为检测和分类重复存框：`Point` 表示一级框已确认但分类未完成，`tl/tc/cl/cc` 表示已经具有二级分类。检测生成时把五种标签投影为 `Point`，分类只使用四种子类，不改写源 JSON。一级完成状态按整张原图确认，必须补漏并明确无目标图片；Point 框不得重叠，每个合法框都存在真实二级目标。分类和分割裁剪只在预览或训练时临时生成。检测框编辑后下游标注保留有效，不增加重新审核流程，编辑者负责语义正确性。

训练组合业务任务基准库和当前工作区内未移除、未过滤且满足所选训练目标门禁的数据，复用现有转换和训练能力。异步执行期间的编辑约束、输入记录和保留方式在具体提交流程中确定，不以前置快照系统实现。ClearML 负责队列、执行、日志、指标和模型产物，普通用户只看到推进任务所需的状态、基本进度、失败信息和结果。

## CVAT integration probe

2026-09-14，用户实际试用后确认原型效果符合预期，CVAT 标注入口与返回体验验证成功。正式开发以同源会话、指定 Job 直达、启动前隐藏全局导航、Menu 位置的“完成”按钮为集成参考，不再将这一交互的可行性作为未决问题。该验收不代表完整平台或生产安全验收完成，本文保持 `proposed`。

CVAT v2.51.0 的隔离原型验证了同源登录与全屏标注返回：自建入口调用 CVAT 会话认证，直接打开指定 Job；前端通过 `window.cvatUI.registerComponent` 加载返回插件，保存标注并确认 Job 为 `completed` 后返回入口。保存失败时留在标注页并允许重试。原型增加页面、插件和反向代理配置，不修改 CVAT 后端，也不重建完整 UI。

原型位于 `lxx@192.168.0.109:/home/lxx/xxtest/work/cvat-bridge`，试用入口为 `http://192.168.0.109:18001/portal/?task=2&job=2`；原有 `18000` 服务保持独立。标注页隐藏 CVAT 全局导航和原 Menu，在 Menu 位置提供“完成”按钮，保存成功后返回平台；不另设悬浮返回按钮。绘框、保存、撤销和帧导航等标注工具保留。隐藏入口不构成权限控制，手动访问后台地址仍由 CVAT 权限决定。

导航隐藏规则放在原型入口 HTML 头部，在应用脚本执行前生效，不以标注组件挂载为条件。仅在标注组件出现后隐藏横幅会留下可点击的加载窗口，加载完成后的布局检查不足以覆盖该问题。布局适配依赖 CVAT DOM 结构。

真实 Chromium 的五项自动化测试全部通过，覆盖未登录入口、登录直达与刷新后完成返回及退出登录、1600 和 1280 宽度下的导航隐藏与工具布局、进入和刷新时 Job 请求仍在等待的导航状态、实际新增框保存失败后留页并重试。保存失败测试通过服务端查询确认失败时标注数量不变，重试成功后新增框持久化。

后续开发在上述远程原型目录查看 `index.html` 的启动前隐藏规则、`return-plugin.js` 的按钮与保存逻辑、`portal.html` 的同源登录和任务入口，以及 `nginx.conf` 的代理配置；`test_bridge.py` 和 `evidence/` 保存回归脚本与截图，`README.md` 提供运行和停用方式。原型复用 `cvat/ui:v2.51.0` 镜像，通过独立 `xxtest-cvat-bridge` 容器挂载这些文件，不覆盖原有 CVAT 服务。原型文件不纳入本仓库 Git；正式组件需按平台职责组织代码并保留上述行为测试。

2026-09-14 验收后，测试机的 CVAT、ClearML 及原型入口共 21 个容器均已停止，Docker 重启策略均设为 `no`，保留容器、镜像、数据和原型文件；试用地址需手动恢复相关服务后才能访问。未发现运行中的 ClearML Agent。此设置针对现存容器，原 Compose 文件仍声明自动重启策略，后续通过 Compose 重建容器时需重新检查，不能将本次停用视为 Compose 配置已修改。

平台接受用户对获授权 Job 导入、导出标注，不要求额外封锁这些能力；CVAT 标注操作不得直接改写平台基准库。最小权限账号采用 CVAT 原生 worker 与 Job 分配能力，本原型不另做独立 worker 权限测试，也未调整现有测试账号权限。

该结果仅证明 CVAT 账号在同源页面间复用会话，不代表独立平台账号的通用 SSO 已完成。插件依赖该版本的前端运行时和状态结构；生产集成仍需验证权限隔离、会话过期、并发编辑、HTTPS 和版本升级。原型的 Job 完成状态不替代平台训练门禁，完整自助平台仍未实现。

## Delivery stages

开发以真实用户流程为增量，不先分别完成六个模块。首轮 Point 标注按检测、分类、分割顺序实现，每个目标完成页面到现场标注保存的真实路径后再增加下一个目标。这是开发顺序，不是自动模型训练编排；ClearML 在后续训练闭环中接入。

返回平台后的业务校验随目标递进：检测不做业务校验；分类只检查是否存在未选择类别的检测框；分割检查 mask 与检测框的位置关系，复用现有规则。文件解析、传输和保存失败仍需反馈，不属于额外业务校验。检测阶段不预建通用校验框架，前述人工标注要求不自动扩展为检测页面的校验项。

**P2：最小自助流程设计。** 从用户选择业务任务和模型、准备数据、完成标注、提交训练到取得结果，逐步识别现有能力与实际缺口。仅为明确的用户流程补充业务状态和接口，不建设独立数据格式或版本管理前置阶段。

数据管理沿用现有文件和训练入口；不安排统一内部格式、SQLite 文件索引及强制入口迁移阶段，取舍见[数据存储提案](2026-09-14-platform-dataset-storage.md#alternatives-considered)。

**P3：用户自助闭环。** 在稳定数据边界上打通上传清洗、标注审核、训练提交、进度反馈和模型获取，使用户不依赖管理员逐次推进。

**P4：基准数据积累。** 管理员按业务任务低频维护基础库和提升合格现场数据，不阻塞用户任务；操作方式由实际维护流程确定。

**P5：扩展与可选功能。** 在主机与 NFS 支持的独立 Agent 模式下按需增加算力，不为单次训练建设跨机器分布式训练。公网反向隧道入口、网盘备份和从机本地数据缓存作为独立后置方向，不阻塞局域网主线。

路线按用户流程依赖推进。只有具体功能证明存在缺口时才定义新的持久状态、接口与实现计划，数据库选型、表结构和版本机制不作为预设要求。

## Detection increment

任务类型为架构型增量（Architectural）：在仓库中新增跨模块的正式平台流程，不以临时验证原型替代交付。核心价值是让用户从平台入口自主完成现场图片的检测框标注，并将结果保存为平台可继续使用的现场数据，无需管理员手动创建标注任务、导出或整理文件。

本增量是正式平台的首个实现范围，使用预置现场和图片，业务任务固定为 Point。页面保留检测、分类、分割三个目标模型的位置，只开放检测；三者共享业务任务内的图片与完整标注，不创建三个独立数据集。业务任务与目标模型的两层关系不要求两级导航，也不要求 CVAT Task/Job 与目标模型一一对应。

页面展示现场、Point 业务任务、图片数量、目标模型、标注状态和“开始／继续标注”入口，不展示图片列表、缩略图或检测框预览，不暴露 CVAT Task/Job 管理。状态需区分待标注、标注中、取回或保存失败、已保存；“已保存”只表示平台文件保存成功，不表示自动检查过检测质量。

用户从检测入口进入 CVAT 编辑，点击“完成”后由插件保存至 CVAT 并返回平台。平台业务流程协调 CVAT 适配取回与格式映射，再交由数据管理保存现场 LabelMe JSON；只有平台文件保存成功后页面才显示“已保存”。CVAT 保存失败时留在标注页重试；平台取回或保存失败时显示错误并允许重试，不要求用户重新标注。继续标注复用已有 CVAT 任务，平台只保存必要的现场数据与 CVAT Task/Job 关联，不借此建设文件索引系统。

职责分配沿用六模块骨架：页面展示与导航，业务流程协调和记录关联，数据管理读取图片及已有 JSON 并保存结果，任务规则提供 Point 检测标注要求和标签定义，CVAT 适配负责创建任务、传入已有框、生成入口及取回映射。ClearML 适配不参与本增量。

`xxtrain.workspace_data.WorkspaceData` 实现预置平铺图片目录和同 stem 标注目录的数据管理存储边界。它通过平台共享类型提供图片真实尺寸和检测框；保存时要求结果恰好覆盖全部预置图片，保留 LabelMe 顶层字段、非矩形标注及矩形附加字段，缺失 JSON 使用相对 `imagePath` 和真实尺寸创建。全部文档在落盘前完成编码，每个 JSON 经同目录临时文件、`fsync` 和 `os.replace` 独立替换；该批次不是多文件事务，前序成功文件可保留，重试以同一结果覆盖。该组件不写原图，也不表示平台流程已经完成保存状态转换。

`xxtrain.business_tasks` 定义 Point 的 `Point/tl/tc/cl/cc` 框标签及三个目标的开放状态。`xxtrain.integrations.cvat.codec` 使用 CVAT 返回的真实标签和保留文本属性 ID 映射矩形标注，文本属性以 JSON 对象携带 LabelMe 矩形附加字段，新建框没有该属性时使用空对象。适配器保留五种框的原标签和空帧，拒绝越界帧、未知标签、轨迹、非矩形及其他无法映射的 shape 属性，不把原始 CVAT 字典或 SDK 对象带入其他包。

`xxtrain.integrations.cvat.CvatClient` 只通过 CVAT HTTP API 创建任务、上传编号图片、校对帧映射、初始化已有标注、分配单一完整 Job 和取回结果。平台业务流程从不依赖 HTTPX 的 `xxtrain.integrations.cvat.preparation` 导入并持久化公开的 `PreparationState`：上传与标注初始化的写入前后分别检查点，已知上传请求 ID 可在 120 秒总期限内继续轮询；无法确认上传请求或标注初始化结果时停止写入并交由管理员对账。适配器不导入平台状态存储，不因重试再次初始化标注。服务令牌请求和浏览器登录、当前用户、退出请求不共享认证或 Cookie，不跟随重定向，也不向非配置源的分页地址发送凭据。配置的 CVAT 源拒绝 URL 用户名或密码，传输失败只向调用方呈现不含底层异常详情的 `PlatformError`。

标注保存不得因本次选择检测而把已有分类标签统一改成 `Point`，不得丢弃已有分割等完整标注信息；统一类别只发生在检测训练数据转换时。本增量不修改基准库，不做上传、现场创建、任务模板管理、检测业务校验或训练提交。分类、分割增量再加入问题图片名称、错误原因与对应 Job/帧的修正入口，不以前置图片预览支撑错误反馈。

检测增量以以下结果验收：

- 预置 Point 现场页面只开放检测，用户无需手动操作 CVAT 后台即可开始或继续标注。
- 进入与刷新期间不出现可点击的 CVAT 全局导航；Menu 位置提供“完成”。
- 新增、修改或删除的检测框正确保存到对应现场 JSON，原图和基准库保持不变，已有分类及分割信息不因检测格式转换被丢弃。
- CVAT 保存成功但平台取回或落盘失败时，不显示“已保存”；重试可完成保存，无需重新标注或创建新任务。
- 返回后的页面不执行检测业务校验，也不将“已保存”解释为检测质量认证。

## Alternatives considered

**继续扩展一次性验证原型作为检测增量交付。** 原型已证明登录、标注入口和返回体验可行，但未落实正式模块职责及现场文件保存；仅扩展原型无法完成用户自主标注并获得平台可用数据的目标。

**首增量同时建设完整自助平台。** 上传、现场管理和训练提交不属于预置数据检测标注的必需路径。先交付入口、编辑与现场保存的最小正式闭环，再按目标和用户能力扩展，避免首增量承担全平台范围。

**首增量提供图片列表与带框预览。** CVAT 已承担图片浏览和标注检查；平台先展示标注任务状态，分类和分割的问题反馈采用错误列表与定位入口，预览按实际使用需要再增加。

**把检测、分类、分割展示为互不相关的独立任务。** 三个目标属于同一 Point 业务任务并共享图片和标注，保留业务任务与目标模型关系可避免数据重复和职责混淆，无需同时建设完整任务管理页面。

**把页面与 CVAT 合并承载业务规则。** CVAT 的页面、会话和标注格式确实需要更多适配，但几何校验和训练资格属于平台任务规则。将其分散到页面、插件和转换程序会产生重复判断与不一致；工具适配集中在连接器，业务协调由平台流程负责。

**以独立服务或零代码依赖实现模块隔离。** 公开接口调用本身就是依赖。当前目标是内部实现隔离、规则单一所有者和单向调用，不是为六个职责增加部署、通信和发布成本。

**建设通用 AutoML、数据平台或完整 MLOps。** 当前用户只需要固定垂类模板的受控闭环，通用工作流、参数编辑和实验分析会扩大权限、状态和支持成本，不能解决管理员单点瓶颈的核心问题。

**让用户直接在 CVAT 和 ClearML 原生页面间推进。** P1 证明两者能够执行专业步骤，但 CVAT 完成后不返回业务流程，ClearML 又暴露过多实验信息，无法共同承担普通用户的步骤门禁和失败反馈。

**把多级业务实现为自动模型 DAG。** 下级任务依赖的是经人工确认的上级标签，而不是某次上级模型执行；自动训练链会混淆标签门禁和模型运行历史。

**把未审核预测直接用于训练或采用半监督训练。** 检测漏检会把真实目标解释为背景，现场初始标签质量不足以支撑可靠自训练。除非独立现成方案先在真实数据上证明有效，否则不重新引入。

**第一版即建设微服务、自建多机调度或分布式训练。** 典型任务只有一两千张图片，主机共享存储和 ClearML 独立 Agent 已足够支持业务闭环；预建分布式控制面没有真实负载依据。

## Acceptance criteria

- 不同业务任务分别组织图片和标注，Point 各训练目标共享任务内数据，不要求先迁移文件格式或建立数据库索引；
- 不同用户和现场工作区的业务引用与查询相互隔离，共享底层文件或隐藏基准不会暴露其他工作区内容；
- 用户移除、过滤和标注状态可以独立变化，重启后保持一致；逻辑移除或过滤不删除原图和已有正式标注；
- 预置的隐藏基准数据能与当前工作区中满足门禁的数据组合为训练输入；
- 自助流程明确训练输入准备、编辑时机与失败反馈，复用现有训练能力，不将完整历史重建系统作为前置验收；

- P3 完成后，普通用户能从 xxtrain 单一入口完成上传、标注、训练和模型获取；P4 与 P5 分别以基准提升和新增独立 Agent 不改变数据所有权为完成条件。

## Risks

- 提前规定数据格式、数据库或版本服务会在实际页面需求明确前扩大开发范围；
- 把多个逻辑状态压成单一枚举会让移除、过滤、标注和基准关系互相覆盖；
- 可变源文件与异步训练的读取时机需要在提交流程中明确，现有目录不自动保证历史输入冻结；
- 过早耦合 CVAT 或 ClearML 对象会让外部生命周期侵入平台身份；
- 当前跨用户共享基准的权属假设可能不适用于未来客户，确认不允许共享时必须先引入新的数据边界；
- 固定模板和局域网单主机数据所有权限制了通用扩展与故障接管能力；部署取舍和后置功能风险见[数据存储提案](2026-09-14-platform-dataset-storage.md)。
