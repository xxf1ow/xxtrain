# Agent Note: 内部自助训练平台

Status: proposed

## Problem

xxtrain 已能把外部标注转换为可训练数据集，并完成训练、预测检查和 ONNX 导出，但现场实施仍依赖管理员逐次整理图片、分发标注、执行命令和反馈进度。标注与训练执行分散在不同工具中，普通用户无法从一个受控入口独立完成固定垂类任务的训练，也没有由 xxtrain 掌握的工作区、权威数据和历史训练输入边界。

平台的目标不是减少一次训练所需的标注量，而是把数据准备、标注推进和训练执行从管理员的单点职责转移给现场实施人员。管理员只定义任务模板、低频维护基准数据并处理少量异常。

## Proposal

本文原有的权威 LabelMe、分类借用框类别、整图清除下游及暂不建设 SQLite 的方向，已由 [SQLite 权威标注存储设计](../../implemented/architecture/2026-09-16-sqlite-annotation-storage.md)部分替代。当前工作区以 SQLite 保存图片登记、显式步骤、父关联和 CVAT 对象映射，按对象清除下游；检测缓存只使用临时 LabelMe 输入。SQLite 运行路径已经通过离线测试、同版本 CVAT 身份往返和真实上传、标注、缓存验收。用户流程、六模块职责、SQLite 之前的检测验收事实和未被替代的约束继续有效。

xxtrain 将在现有训练核心之外增加一个内部自助训练平台。普通用户通过 xxtrain 的统一入口选择开发者预定义的业务任务和训练目标，在当前现场工作区上传图片、完成标注或审核、提交单模型训练、查看进度并取得模型。CVAT 提供标注画布，ClearML 提供训练排队和执行，xxtrain 保留业务流程、权威数据和跨平台状态的所有权。

P1 已用 4 张图片和单类别 `point-detect` 任务验证真实链路：CVAT Job 完成 4 个框后导出 COCO，xxtrain 转换为 3 张训练图片和 1 张验证图片，ClearML Agent 在真实 GPU 上完成一轮训练并保存 ONNX，产物可通过接口取回且通过 ONNX 结构校验。该结果证明组件组合可行，也表明 CVAT 的完成与返回路径、ClearML 的普通用户信息范围都需要由 xxtrain 包装。

第一版供内部人员在局域网使用，采用一台 Ubuntu 主机承载平台和权威数据、多台 Ubuntu ClearML Agent 执行独立训练的部署。平台入口、数据层和两个连接器是同一应用内的逻辑组件，不拆成微服务，也不增加独立消息队列、对象存储或通用工作流引擎。部署与数据格式由[平台部署与数据集存储](2026-09-14-platform-dataset-storage.md)所有。

## Product boundary

- 普通用户只能选择开发者定义的业务任务、训练目标和训练预设，不能创建任务结构、修改标签定义或编辑底层训练参数；
- 每次训练运行只训练所选业务任务中的一个模型，多模型业务由用户分别选择训练目标提交，平台不编排自动模型 DAG；
- xxtrain 是普通用户唯一入口，ClearML 只作为管理员后台，CVAT 只暴露当前标注步骤所需的最小界面；
- 不维护 CVAT 或 ClearML 的中文分支；xxtrain 负责标注入口、提交、状态同步、失败反馈和返回路径；
- 第一版不建设通用 AutoML、通用数据平台、完整 MLOps、商业多租户、复杂鉴权、计费或单次训练跨机器分布式执行；从机通过只读 NFS 访问主机数据，不维护权威数据同步服务；
- FiftyOne、ClearML Data 和 ClearML Pipeline 不进入第一版；自动清洗先服务普通上传路径，不提前建设通用数据探索平台；
- 沿用现有图片和本地训练入口；工作区 SQLite 只保存登记、标注与对象映射，不要求基准库、Scenario 或训练入口迁入统一格式；
- 管理员低频兜底和基准数据提升不能成为用户继续标注或训练的前置条件。

## Component responsibilities

平台划分为六个逻辑模块，使每项业务规则和数据都有明确所有者，允许页面、标注与训练分别演进。页面可以是独立前端工程，其余模块可以是同一后端项目中的 Python 包；不要求六个服务、仓库或独立发布单元。物理包结构按实际实现确定，现有训练核心继续复用。

| 模块 | 负责 | 不负责 |
|---|---|---|
| 页面 | 接收用户操作，展示业务状态、校验错误和结果，提供标注与问题定位入口 | 判断训练资格、计算标注位置关系、直接操作文件或第三方 API |
| 平台业务流程 | 用户和现场工作区归属、任务与模型选择、步骤协调、业务状态及外部对象关联；依据规则校验结果控制训练提交 | 实现几何规则、解析 CVAT 格式、执行模型训练 |
| 数据管理 | 原图和 SQLite 工作区事实的读取与保存、上传去重、基准库与现场数据的存储边界 | 判断业务标注合格性、管理 CVAT Job、提交训练 |
| 任务规则与训练核心 | 任务标签语义、训练目标要求、位置匹配和标注校验、数据转换、模型训练 | 用户会话、网页跳转、CVAT 和 ClearML 对象管理 |
| CVAT 适配 | 创建与分配标注任务、传入图片及已有标注、取回与格式映射、Job/帧定位、会话接入及薄前端插件 | 判断训练资格、直接改写基准库、启动训练 |
| ClearML 适配 | 提交排队、查询执行状态和日志、获取产物；Agent 执行入口调用现有训练核心 | 判断样本合格性、解释标注语义、管理用户工作区 |

主要调用关系如下，表示逻辑依赖，不要求模块间网络通信：

```text
页面 → 平台业务流程
          ├─ 数据管理
          ├─ 任务规则与训练核心
          ├─ CVAT 适配
          └─ ClearML 适配

ClearML Agent 执行入口 → 任务规则与训练核心
```

跨包只使用公开函数和类型，不访问私有实现、不直接修改其他模块拥有的文件或数据库表，不形成循环依赖。CVAT 和 ClearML SDK 对象停留在各自适配模块，业务流程与规则使用平台定义的数据。后端模块之间可以普通 Python 调用协作，不为隔离而增加 HTTP、通用插件框架或无实际需要的抽象类。

平台业务流程负责跨模块协调：CVAT 适配返回标注与原生对象身份，数据管理在事务内保存工作区标注和映射，任务规则组件执行校验，页面展示错误和修正入口。CVAT 适配不直接调用数据管理或校验组件。插件只保存并返回，不执行 Point 业务规则；返回平台后的校验与训练前校验复用同一套规则。保存成功、CVAT Job 完成和允许训练是不同事实；业务校验失败时保留用户标注，允许返回对应 Job 和问题帧修正。

数据管理提供训练输入访问，平台业务流程确定输入范围与预设并检查训练资格，ClearML 适配负责交付执行。Agent 在本地工作目录调用现有核心进行转换和训练，不把算法逻辑写进提交接口，也不让 ClearML 成为数据集管理系统。六模块是职责约束，不是必须先全部搭建完成的空包目录。

## Domain and data ownership

**业务任务**是 Point、knob、light 等独立数据管理范围，由开发者通过任务模板定义共享标签和可选训练目标。**训练目标**定义一个模型的转换规则、标注门禁和训练预设；Point 检测、分类和分割是同一业务任务的三个目标。**工作区**是某个用户在某个现场和业务任务下持续上传、标注和训练的可变数据范围。**正式标注**由人工创建，或由人工审核通过的模型候选转化而来；能否进入训练由所选目标的门禁判断。**训练运行**是用户选择业务任务和训练目标后提交给 ClearML 排队和执行的一次单模型训练；输入与配置如何记录由具体提交流程确定。

xxtrain 拥有任务模板、工作区、正式标注、步骤门禁和跨平台业务流程。业务任务分别组织原图和标注数据库，跨业务任务允许重复存储。每个工作区的 SQLite 只保存图片登记、标注及当前 CVAT 对象映射，不保存业务阶段、页面计数或训练历史。数据组织与部署由[数据存储提案](2026-09-14-platform-dataset-storage.md)所有，表结构与对象身份由 [SQLite 设计](../../implemented/architecture/2026-09-16-sqlite-annotation-storage.md)所有。CVAT 和 ClearML 对象用于专业步骤与业务映射，不替代平台的业务任务定义。

用户数据的业务引用和查询范围按用户、业务任务和现场工作区隔离。文件组织不得暴露其他工作区的数据。每个业务任务拥有一套对普通用户隐藏、跨用户共享的基准数据，各训练目标按门禁选择合格样本；只有管理员提升后的用户数据才跨工作区使用。该设计假设同一业务任务的数据允许跨用户进入共享基准；若实际权属不允许共享，必须重新设计客户级数据边界。

基准数据是基础训练样本库，不建设固定评测集。同业务任务上传与基准库按文件哈希严格去重，同一现场上传图片之间按相似度阈值去重；命中基准库的重复上传不建立标注副本。已有图片缺少某训练目标标注时，通过编辑已有 JSON 补充，不因重复上传判定为标注齐全。现有 LabelMe 数据组织及清理范围见[数据存储提案](2026-09-14-platform-dataset-storage.md)。

多次上传直接追加到当前工作区，不保留 `upload_batch_id`。上传候选经过去重后接纳或清理；不建设用户找回、用户调整相似度阈值、逻辑移除或文件变更监听。候选标注、CVAT Job 引用、训练缓存、日志和指标是过程产物，不进入长期权威数据。

## State derivation

平台不保存业务阶段、图片计数、标签有效性或“已开始”标记。唯一权威事实是当前用户工作区中已经登记的原图及 SQLite 标注；临时上传目录和未登记残留不参与页面判断。预置检测闭环的 `StateStore` 状态枚举和远程请求检查点不进入上传流程。页面在读取、上传处理、CVAT 同步和缓存生成结束后，从数据库事实与运行产物重新计算有效图片数、已标注图片数、上游标签是否完整和各按钮是否可用。

检测图片有一个或多个正式框，或数据库中存在显式检测负样本记录时，才计入已标注。所有有效图片均已标注且至少 50 张工作区图片含检测框时，检测“开始训练”按钮可用；有效负样本进入检测数据集作为背景样本，但不计入 50 张门槛。分类和分割以后分别以完整上游标签开放；完成当前标签后可跳过当前模型训练并进入下一个目标。

CVAT 缓存以目标和该目标输入内容的指纹定位 Job 引用；检测指纹由有效图片和检测标签构成。相同指纹复用未完成 Job，不同指纹创建新 Job，旧 Job 保留但不再同步。训练缓存以当前训练输入指纹定位；命中目录表示缓存可复用，不命中则按钮可重新生成。缓存、Job 引用和进程内写锁都不是业务状态；写锁只在上传、去重、同步、缓存生成及未来训练运行期间拒绝并发写入。未来真实训练运行期间也拒绝上传，取消或结束后重新从权威文件计算页面。

## Annotation and training flow

依赖上级标签的训练目标要求这些标签完整、合格，不依赖上级训练运行、checkpoint 或执行历史。用户在 CVAT 编辑页完成一次 Job 即声明该批标注已审核；平台不记录逐图浏览或审核进度。上级标签可以人工创建、从现有数据集导入或由已有模型生成候选；候选只初始化 CVAT，不进入权威数据库，回收后才按正式入口写入。未完成当前目标标注的数据可以留在工作区，但不能进入该目标训练，也不能解释为负样本。上级标签不合格时平台阻止下级训练，不自动启动其他模型补救。

Point 检测、分类和分割共享业务任务的原图和 SQLite 标注。检测框、分类和分割是具有独立稳定 UUID、`step_key` 和可空 `parent_id` 的记录；分类与分割显式关联可信的 Point 框，不借用框类别表达自己的身份。检测生成时把五种现有框标签投影为一个类别，不改写数据库事实。空图只有显式检测负样本记录时才有效，不能自动解释为负样本。分类和分割裁剪只在编辑、预览或训练时临时生成。上游变化按任务依赖与目标对象清除下游记录；同图无关对象保持不变。

训练组合业务任务基准库和当前工作区中满足所选训练目标门禁的数据，复用现有转换和训练能力。工作区标签完整性和样本门槛不依赖基准库或管理员模型；两者只分别影响训练输入组合和可选候选标注生成。异步执行期间的编辑约束、输入记录和保留方式在具体提交流程中确定，不以前置快照系统实现。ClearML 负责队列、执行、日志、指标和模型产物，普通用户只看到推进任务所需的状态、基本进度、失败信息和结果。

## CVAT integration probe

用户已在当前 SQLite 部署中完成真实上传、CVAT 标注返回和检测缓存生成，确认入口与标注页面没有问题。该验收覆盖当前检测交互，不构成分类、分割、真实训练、完整平台、生产或安全验收；本文保持 `proposed`。

CVAT v2.51.0 的隔离原型验证了同源登录与全屏标注返回：自建入口调用 CVAT 会话认证，直接打开指定 Job；前端通过 `window.cvatUI.registerComponent` 加载返回插件，保存标注并确认 Job 为 `completed` 后返回入口。保存失败时留在标注页并允许重试。原型增加页面、插件和反向代理配置，不修改 CVAT 后端，也不重建完整 UI。

原型位于 `lxx@192.168.0.109:/home/lxx/xxtest/work/cvat-bridge`，试用入口为 `http://192.168.0.109:18001/portal/?task=2&job=2`；原有 `18000` 服务保持独立。标注页隐藏 CVAT 全局导航和原 Menu，在 Menu 位置提供“完成”按钮，保存成功后返回平台；不另设悬浮返回按钮。绘框、保存、撤销和帧导航等标注工具保留。隐藏入口不构成权限控制，手动访问后台地址仍由 CVAT 权限决定。

导航隐藏规则放在原型入口 HTML 头部，在应用脚本执行前生效，不以标注组件挂载为条件。仅在标注组件出现后隐藏横幅会留下可点击的加载窗口，加载完成后的布局检查不足以覆盖该问题。布局适配依赖 CVAT DOM 结构。

真实 Chromium 的五项自动化测试全部通过，覆盖未登录入口、登录直达与刷新后完成返回及退出登录、1600 和 1280 宽度下的导航隐藏与工具布局、进入和刷新时 Job 请求仍在等待的导航状态、实际新增框保存失败后留页并重试。保存失败测试通过服务端查询确认失败时标注数量不变，重试成功后新增框持久化。

正式组件把经验证的行为分别放在 `xxtrain.platform.app`、包内页面资源、`src/xxtrain/integrations/cvat/ui/return-plugin.js` 和 `deploy/platform/`，不复制原型凭据、图片或品牌文字。CVAT UI 镜像固定为 `cvat/ui:v2.51.0`；构建在应用脚本执行前插入导航隐藏样式，并在插入点不匹配时失败。返回插件核对当前 Job，阻止正在绘制时返回，依次保存帧与标注，确认 completed 状态后只返回 `/platform/?returned=1`；页面再通过受 CSRF 保护的 POST 取回并保存平台标注。CVAT 保存失败时插件留在当前页，CVAT completed 状态不表示平台已经保存。

2026-09-14 验收后，测试机的 CVAT、ClearML 及原型入口共 21 个容器均已停止，Docker 重启策略均设为 `no`，保留容器、镜像、数据和原型文件；试用地址需手动恢复相关服务后才能访问。未发现运行中的 ClearML Agent。此设置针对现存容器，原 Compose 文件仍声明自动重启策略，后续通过 Compose 重建容器时需重新检查，不能将本次停用视为 Compose 配置已修改。

平台接受用户对获授权 Job 导入、导出标注，不要求额外封锁这些能力；CVAT 标注操作不得直接改写平台基准库。最小权限账号采用 CVAT 原生 worker 与 Job 分配能力，本原型不另做独立 worker 权限测试，也未调整现有测试账号权限。

该结果仅证明 CVAT 账号在同源页面间复用会话，不代表独立平台账号的通用 SSO 已完成。插件依赖该版本的前端运行时和状态结构；生产集成仍需验证权限隔离、会话过期、并发编辑、HTTPS 和版本升级。原型的 Job 完成状态不替代平台训练门禁，完整自助平台仍未实现。

## Delivery stages

开发以真实用户流程为增量，不先分别完成六个模块。检测和 SQLite 闭环之后，分类与指针分割作为同一阶段交付，共用裁剪和编辑流程，实施时先贯通分类再接分割；这不是自动模型训练编排。后续目标的标注表达、数量口径和缓存规则由 [Point 分类与指针分割闭环](2026-09-16-point-classification-segmentation.md)所有。ClearML 在后续训练闭环中接入。

返回平台后的业务校验由目标规则决定：检测保持现状；分类检查每张裁剪图恰好一个类别；指针分割检查每张至少一条两点 line，来源由显式框关联确定，不再通过 mask 位置配对。文件解析、传输和保存失败仍需反馈，不预建通用校验框架。

**P2：最小自助流程设计。** 从用户选择业务任务和模型、准备数据、完成标注、提交训练到取得结果，逐步识别现有能力与实际缺口。检测闭环、SQLite 权威存储、对象身份运行路径及真实 CVAT 验收已经完成；后续联合交付分类和指针分割的数据准备闭环。保留现有上传与页面，不建设历史版本系统。

存储迁移复用现有训练转换，数据库是标注权威而非 JSON 索引。无价值验收数据无需迁移，真实存量数据保持不动；不开发迁移工具。管理员页面、已有标注导入与基准归档后置到 Point 三模型闭环稳定之后，详见 [SQLite 设计的后续范围](../../implemented/architecture/2026-09-16-sqlite-annotation-storage.md#deferred-model-and-baseline-workflow)。

**P3：用户自助闭环。** 在稳定数据边界上打通上传清洗、标注审核、训练提交、进度反馈和模型获取，使用户不依赖管理员逐次推进。

**P4：基准数据积累。** 管理员按业务任务低频维护基础库和提升合格现场数据，不阻塞用户任务；操作方式由实际维护流程确定。

**P5：扩展与可选功能。** 在主机与 NFS 支持的独立 Agent 模式下按需增加算力，不为单次训练建设跨机器分布式训练。公网反向隧道入口、网盘备份和从机本地数据缓存作为独立后置方向，不阻塞局域网主线。

路线按用户流程依赖推进。只有具体功能证明存在缺口时才定义必要事实记录、接口与实现计划；当前三表 SQLite 不预设更多流程状态、通用版本机制或其他训练目标页面。

## Detection increment

上传与模型操作的过程提示显示在各自操作区域，使用强调背景和加载图标，并持续到请求结束；失败信息留在对应区域。成功反馈使用 8 秒后消失的气泡通知，不占用常驻布局，也不持久化通知状态。上传气泡展示本次选择数量与服务端返回的现场有效图片总数；当前 HTTP 接口未返回本批过滤、接纳数量，页面不以总数差值推测它们。展示本批过滤、留存统计需后续将数据接纳层的 `UploadResult` 传递到上传响应。

任务类型为架构型增量（Architectural）：在仓库中新增跨模块的正式平台流程，不以临时验证原型替代交付。核心价值是让用户从平台入口自主完成现场图片的检测框标注，并将结果保存为平台可继续使用的现场数据，无需管理员手动创建标注任务、导出或整理文件。

本增量是正式平台的首个实现范围，使用预置现场和图片，业务任务固定为 Point。页面保留检测、分类、分割三个目标模型的位置，只开放检测；三者共享业务任务内的图片与完整标注，不创建三个独立数据集。业务任务与目标模型的两层关系不要求两级导航，也不要求 CVAT Task/Job 与目标模型一一对应。

页面以“业务任务 / 现场”为上下文，顶部共享区只展示有效图片总数与上传入口；选定文件后立即上传。检测、分类、分割按依赖顺序纵向排列，每个模型独立展示“已标注图片 M / N 张”、“开始标注”和“开始训练”。计数单位是图片，不是框或 mask；检测负样本计入已标注数量，但不计入训练门槛。检测展示文件派生的真实计数；分类、分割尚未开放，分子显示“—”且两个按钮禁用，不能伪造为零。页面不展示图片列表、缩略图或检测框预览，不暴露 CVAT Task/Job 管理，也不保存业务阶段。

有效图片大于零即可开始检测标注。检测要求所有原图已标注且至少 50 张有框图片，阈值包含 50；无需先训练当前模型才能进入下一步。分类和分割的开放仍待实现，采用[裁剪图完整性规则](2026-09-16-point-classification-segmentation.md#state-derivation-and-user-flow)，不设置独立数量门槛。当前“开始训练”只生成检测训练缓存，页面明确说明该范围，缓存已生成时显示“训练缓存已生成”。按模型成行排列使标注进度与操作归属直接对应，避免跨模型共用一个标注总数造成歧义。

正式 HTTP 入口使用 CVAT 浏览器会话识别用户，随后检查预置现场归属。缺少或失效的会话返回 401，登录凭据被 CVAT 拒绝时返回 401，已认证但不属于现场的用户返回 403，CVAT 或本地流程操作失败返回 502；响应不暴露服务令牌、凭据、CVAT 响应正文或本地绝对路径。所有写请求都检查同源 Origin 和页面 CSRF 令牌，包括登录与退出。`POST /platform/api/images` 接收一个或多个 `images` 文件，认证与归属检查先于 multipart 解析，临时文件以生成名称写入运行目录的 `staging/` 并在操作结束时清理。`POST /platform/api/detection/start`、`sync` 和 `cache` 只接受严格空 JSON 对象，不能由浏览器覆盖目标、CVAT ID 或文件路径。

用户从检测入口进入 CVAT 编辑，点击“完成”后由插件保存至 CVAT 并返回平台。平台业务流程协调 CVAT 适配取回标注与原生 ID，再交由数据管理按稳定 UUID 规划变化并在 SQLite 事务内保存标注和映射；页面随后刷新计数。CVAT 保存失败时留在标注页重试；平台取回或保存失败时保留返回参数并提示刷新页面重试，不要求用户重新标注。返回参数存在期间，页面禁止上传、打开标注和生成缓存，避免替换待同步 Job 或改变其输入指纹；同步成功后移除参数并恢复数据库派生按钮。继续标注只复用当前输入指纹对应的未完成 Job，已完成 Job 触发新任务创建。

职责分配沿用六模块骨架：页面展示与导航，业务流程协调和记录关联，数据管理读取已登记图片及数据库标注并保存结果，任务规则提供 Point 检测标注要求和标签定义，CVAT 适配负责创建任务、传入已有框、生成入口及取回原生对象映射。ClearML 适配不参与本增量。

`xxtrain.workspace_data.WorkspaceData` 从工作区根目录使用 `images/` 和 `annotations.db`，并按完整 SHA-256 和 DCT 感知哈希接纳临时图片。图片只有落盘且登记成功后才参与查询；未登记残留不被自动接纳。检测摘要从矩形和显式负样本记录派生。`AnnotationRepository` 在一个事务内校验并写入标注与当前 CVAT 映射；失败保留原标注和映射。SQLite 不与图片文件系统共享事务，数据库与原图共同构成备份范围。

`xxtrain.business_tasks` 定义 Point 的 `Point/tl/tc/cl/cc` 框标签、检测/分类/分割步骤、父关系及依赖。`xxtrain.integrations.cvat.codec` 在共享平台类型与 CVAT 矩形之间转换；初始化暂时把平台 UUID 放入受控附加字段以关联服务端响应，建立原生 ID 映射后移除令牌。常规回收以 CVAT 原生 ID 定位对象，拒绝越界帧、未知标签、轨迹和非矩形，不把原始 CVAT 字典或 SDK 对象带入其他包。

`xxtrain.integrations.cvat.CvatClient` 通过 CVAT HTTP API 创建任务、上传编号图片、校对帧映射、初始化已有标注、分配单一完整 Job 和取回结果。初始化 PUT 响应或已初始化任务的恢复读取必须建立完整 UUID/原生 ID 映射后才返回可发布 Job；缺失或重复令牌失败关闭。准备过程有 120 秒总期限。`job_is_unfinished` 读取 Job 的字符串 `state`，仅 `completed` 表示完成；畸形响应产生 `PlatformError`。服务令牌请求和浏览器会话请求不共享认证或 Cookie，不跟随重定向，也不向非配置源的分页地址发送凭据。

`xxtrain.platform.config` 从严格 JSON 对象加载工作区、独立运行目录和所属用户，路径相对配置文件解析，不保存 CVAT 服务令牌。`AnnotationService` 从数据库事实派生图片数、已标注数、有框数及缓存资格，不写业务状态或准备检查点。上传、开始标注、同步及缓存生成持有同一个非阻塞进程锁；并发写操作立即失败。开始标注只复用检测目标和当前指纹对应的未完成 Job，完整身份映射落库后才发布 `JobRef`。同步拒绝旧 Job，先失效受影响对象的历史 Job 引用和发布指纹，再在一个数据库事务内提交标注变化与新增映射；事务失败保持数据库原状，重启可从已发布指纹和数据库映射恢复。缓存生成要求全部图片已标注且至少 50 张含框。

标注保存不得因本次选择检测而把已有分类标签统一改成 `Point`，不得丢弃已有分割等完整标注信息；统一类别只发生在检测训练数据转换时。本增量不修改基准库，不做上传、现场创建、任务模板管理、检测业务校验或训练提交。分类、分割增量再加入问题图片名称、错误原因与对应 Job/帧的修正入口，不以前置图片预览支撑错误反馈。

检测增量以以下结果验收：

- 预置 Point 现场页面只开放检测，用户无需手动操作 CVAT 后台即可开始或继续标注。
- 进入与刷新期间不出现可点击的 CVAT 全局导航；Menu 位置提供“完成”。
- 新增、修改或删除的检测框正确保存到对应工作区数据库，原图和基准库保持不变，未受影响对象的分类及分割记录不因检测同步被丢弃。
- CVAT 保存成功但平台取回或落盘失败时，页面保留现有计数并显示错误；刷新可重试保存，无需重新标注或创建新任务。
- 返回后的页面不执行检测业务校验，也不将已标注数量解释为检测质量认证。

SQLite 之前的检测增量自动浏览器验收使用独立生成的两图临时工作区，覆盖首次创建、完成后创建新 Job、全页刷新、导航隐藏、框的移动、新增和删除、CVAT 保存失败重试、平台同步失败后刷新重试，以及从磁盘回读当时的 LabelMe JSON。该阶段验收确认原图和独立基准文件哈希不变，并保留分类标签、非矩形标注和根字段；这些事实证明原检测流程，不证明当前 SQLite 对象身份往返。

SQLite 之前的平台进程重启后同一 Job 复用由独立手工验收确认，不属于自动浏览器场景。授权验收目录 `/home/lxx/xxtest/work/point-platform-task6-20260914/.superpowers/platform-acceptance/restart-reuse.log` 保存 `restart_reuse=true`；该记录由 `sh stop_platform.sh`、`sh start_platform.sh`、`probe_platform_start.py` 和状态中 Job 路径的比较生成。该结果只确认当时的检测增量，不证明当前数据库映射恢复；完整平台仍保持 `proposed`，分类、分割和训练未实现。

## Upload and detection-cache increment

本增量将预置图片替换为默认用户、Point 任务的批量上传。工作区保存用户接纳原图和 `annotations.db`；基准库单独按业务任务组织，管理员可见，且本增量不实现基准维护或读取。运行产物位于工作区外：CVAT 缓存按检测目标和输入指纹保存 Job 引用，训练缓存按相同输入指纹保存生成数据集。平台为默认用户分配最低权限的 CVAT worker 账号，使用 Point 检测标签及矩形标注模板创建 Job。

当前服务与缓存边界由 `AnnotationService`、`RuntimeCache` 和 `build_detection_cache` 提供。服务和 HTTP 页面支持上传接纳、Job 创建与同步、门槛检查和缓存生成；页面在一个请求执行期间禁用全部写操作，缓存按钮使用服务返回的资格和已生成标志。运行缓存用原子 JSON 保存目标、输入指纹和 `JobRef`；当前对象映射保存在 SQLite。缓存构建把完成的数据库检测标注物化为临时 LabelMe 源，使用 Point 检测投影生成数据集后原子发布。发布前，YAML 与训练列表指向最终缓存路径，图片软链接改为相对路径，保证目录重命名后仍可读取。负样本保留为空 YOLO 标签，不完整空图不进入缓存。离线服务、真实 HTTP 组合及页面脚本测试覆盖数据库恢复、Job 替换、事务失败、上传清理、计数刷新、缓存门槛、发布后的图片引用和五种框标签的检测输出。SQLite 之前的真实验收保留为原检测流程证据；当前对象身份和缓存运行证据由 [SQLite 设计](../../implemented/architecture/2026-09-16-sqlite-annotation-storage.md#live-acceptance-status)所有。两次验收都不覆盖分类、分割或真实训练。

上传在临时目录完成严格哈希和任务相似度去重后接纳；图片先落盘，再提交数据库登记。当前数据层以 DCT 感知哈希距离不大于 2 判定相似候选，优先保留既有工作区图片，并将检测输入指纹限定为排序后的图片 SHA-256 与规范化检测框或显式负样本。页面仅显示有效图片数和已标注图片数。检测标注数包含有框图片和显式有效负样本；空图未声明有效负样本时不计入。上传、去重和缓存生成期间拒绝其他写操作，完成后从数据库事实重新计算页面和门禁。

用户打开检测标注时，平台由已登记图片和检测标注计算输入指纹；命中缓存则重用未完成且映射完整的 Job，否则从当前正式检测标注新建 Job。用户完成并同步后，平台按 CVAT 原生 ID 和稳定 UUID 应用对象级变化。相同内容的上传、Job 打开、同步和缓存生成必须收敛：已接纳图片不重复登记，相同指纹的未完成 Job 和已生成缓存可复用，无修改回收保留对象及下游。缓存生成要求所有有效图片均已标注，且至少 50 张工作区图片含检测框；有效负样本保留为 YOLO 背景样本但不计入 50 张。“开始训练”只生成检测训练缓存，不提交训练；已生成时按钮显示“训练缓存已生成”并禁用。

分类、分割、模型候选生成、基准库拼接、管理员入口、真实训练和 ClearML 保持后续范围。将来每个目标仅显示和写入自己的标注；只读上游标注显示只有在小范围 CVAT 改动能够安全实现时才加入。管理员模型仅在用户主动生成候选标签时使用；候选标签内容而非模型版本决定相应 Job 输入是否改变，模型版本不构成工作区状态或输入指纹。

## Alternatives considered

**继续扩展一次性验证原型作为检测增量交付。** 原型已证明登录、标注入口和返回体验可行，但未落实正式模块职责及现场文件保存；仅扩展原型无法完成用户自主标注并获得平台可用数据的目标。

**首增量同时建设完整自助平台。** 上传、现场管理和训练提交不属于预置数据检测标注的必需路径。先交付入口、编辑与现场保存的最小正式闭环，再按目标和用户能力扩展，避免首增量承担全平台范围。

**首增量提供图片列表与带框预览。** CVAT 已承担图片浏览和标注检查；平台先展示标注任务状态，分类和分割的问题反馈采用错误列表与定位入口，预览按实际使用需要再增加。

**把检测、分类、分割展示为互不相关的独立任务。** 三个目标属于同一 Point 业务任务并共享图片和标注，保留业务任务与目标模型关系可避免数据重复和职责混淆，无需同时建设完整任务管理页面。

**把页面与 CVAT 合并承载业务规则。** CVAT 的页面、会话和标注格式确实需要更多适配，但几何校验和训练资格属于平台任务规则。将其分散到页面、插件和转换程序会产生重复判断与不一致；工具适配集中在连接器，业务协调由平台流程负责。

**以独立服务或零代码依赖实现模块隔离。** 公开接口调用本身就是依赖。当前目标是内部实现隔离、规则单一所有者和单向调用，不是为六个职责增加部署、通信和发布成本。

**建设通用 AutoML、数据平台或完整 MLOps。** 当前用户只需要固定垂类模板的受控闭环，通用工作流、参数编辑和实验分析会扩大权限、状态和支持成本，不能解决管理员单点瓶颈的核心问题。

**让用户直接在 CVAT 和 ClearML 原生页面间推进。** P1 证明两者能够执行专业步骤，但 CVAT 完成后不返回业务流程，ClearML 又暴露过多实验信息，无法共同承担普通用户的步骤门禁和失败反馈。

**把多级业务实现为自动模型 DAG。** 下级任务依赖的是经人工确认的上级标签，而不是某次上级模型执行；自动训练链会混淆标签门禁和模型运行历史。

**把未审核预测直接用于训练或采用半监督训练。** 检测漏检会把真实目标解释为背景，现场初始标签质量不足以支撑可靠自训练。除非独立现成方案先在真实数据上证明有效，否则不重新引入。

**第一版即建设微服务、自建多机调度或分布式训练。** 典型任务只有一两千张图片，主机共享存储和 ClearML 独立 Agent 已足够支持业务闭环；预建分布式控制面没有真实负载依据。

## Acceptance criteria

- 不同业务任务分别组织图片和标注，Point 各训练目标共享任务内原图和 SQLite 标注，不要求迁移真实存量或现有训练格式；
- 不同用户和现场工作区的业务引用与查询相互隔离，共享底层文件或隐藏基准不会暴露其他工作区内容；
- 用户工作区只保留已登记图片及正式标注；上传候选去重后接纳或清理，页面和门禁始终从数据库事实重新计算；
- 预置的隐藏基准数据能与当前工作区中满足门禁的数据组合为训练输入；
- 自助流程明确训练输入准备、编辑时机与失败反馈，复用现有训练能力，不将完整历史重建系统作为前置验收；

- P3 完成后，普通用户能从 xxtrain 单一入口完成上传、标注、训练和模型获取；P4 与 P5 分别以基准提升和新增独立 Agent 不改变数据所有权为完成条件。

## Risks

- 将工作区三表 SQLite 扩展为通用格式、流程状态或版本服务会扩大当前范围；
- 把多个逻辑状态压成单一枚举会让移除、过滤、标注和基准关系互相覆盖；
- 未确认的 CVAT 创建请求可能留下不再使用的 Job；Job 不属于权威数据，下一次操作按当前输入重新创建或命中缓存，不以业务状态对账补救；
- 可变源文件与异步训练的读取时机需要在提交流程中明确，现有目录不自动保证历史输入冻结；
- 过早耦合 CVAT 或 ClearML 对象会让外部生命周期侵入平台身份；
- 当前跨用户共享基准的权属假设可能不适用于未来客户，确认不允许共享时必须先引入新的数据边界；
- 固定模板和局域网单主机数据所有权限制了通用扩展与故障接管能力；部署取舍和后置功能风险见[数据存储提案](2026-09-14-platform-dataset-storage.md)。
