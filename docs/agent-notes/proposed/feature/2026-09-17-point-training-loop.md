# Agent Note: Point 自助训练与结果交付

Status: proposed

## Problem

Point 检测、分类和指针分割已能完成上传、标注与训练缓存准备，但现场用户仍不能从平台执行真实训练并取得部署模型。多个模型需要连续提交、后台排队，不能要求用户取得前一个模型后才能提交下一个；训练输入保护也不能变成整个工作区只能提交一次训练的限制。

## Proposal

提交身份、同缓存重新训练及对应按钮规则由 [按训练输入唯一提交](../simplification/2026-09-17-training-input-identity.md) 部分替代。本文继续拥有训练执行和交付规则；Implementation progress 描述现有代码，不表示已完成该简化设计。

用户完成标注后，能够直接在平台启动所选模型的真实训练、查看进度并下载训练结果，无需管理员手动执行命令。平台直接提交 ClearML 任务，Agent 复用现有训练核心；不使用预建 ClearML 模板任务或自动模型 DAG。

本文拥有真实训练提交、运行关联、编辑限制、任务页面和部署产物交付设计，细化[平台总体提案](2026-07-30-self-service-training-platform.md)和[部署与存储提案](2026-09-14-platform-dataset-storage.md)中未确定的训练运行规则。[Point 三模型数据准备](../../implemented/feature/2026-09-16-point-classification-segmentation.md)继续拥有标注、裁剪、门禁和缓存规则，[SQLite 标注存储](../../implemented/architecture/2026-09-16-sqlite-annotation-storage.md)继续拥有标注事实和对象关联。业务任务、提交、运行关联、编辑限制、任务页面和交付已有离线实现；真实 ClearML Server、Agent 和 GPU 验收仍未完成。

## Responsibilities

| 组件 | 本阶段职责 |
|---|---|
| 自建页面 | 工作区提交反馈；独立的用户训练任务列表、进度、结果、下载和取消入口 |
| 平台业务层 | 检查资格、协调缓存准备、关联用户和训练运行、派生编辑限制及按钮状态 |
| 数据管理 | 提供当前标注和缓存输入；保护运行引用的缓存，不解释 ClearML 状态 |
| 业务任务与训练核心 | 定义目标、训练配置、主要指标和下载内容；执行训练、导出与优化 |
| ClearML 适配及 Agent 入口 | 提交队列、查询任务、取消和产物传输；调用训练核心并上报执行信息 |
| CVAT 适配 | 沿用目标隔离标注与回收；训练期间平台不开放标注入口或接纳标注写入 |

这些职责仍是同一应用内的逻辑模块，不增加调度服务、消息队列、通用工作流或算法后端抽象。ClearML SDK 对象留在适配层；页面不直连 ClearML 管理 API。

## Queue and execution

提交顺序为：校验当前目标资格、生成或复用缓存、提交 ClearML 队列、空闲 Agent 领取、训练、导出并优化 ONNX、整理并发布产物、任务完成。缓存准备期间沿用现有写操作互斥；只有入队成功才提示成功。

本阶段每台训练机安装一个普通 ClearML Agent，同时执行一个训练任务。所有训练 Agent 监听同一队列，按入队时间领取任务；没有空闲 Agent 时继续排队。多机并行不保证完成顺序，不自行根据瞬时 GPU 利用率调度。主机可运行 Agent，但需给 CVAT、平台和 ClearML Server 留出资源。

同一工作区可以连续提交不同目标，不依赖其他模型训练成功或模型下载。不设置用户任务配额，也不设置工作区总任务配额；同输入重复提交按唯一输入提案返回既有运行，不提供同缓存重新训练，不使用失败任务的 checkpoint 恢复。

Agent 通过主机共享目录读取所选缓存，不把训练缓存上传到 ClearML Data。共享输入只读；模型 YAML、框架运行缓存、日志、checkpoint 和导出文件写入 Agent 本地的独立运行目录。训练入口必须直接消费已准备的数据集，不能重新转换权威标注，也不能向共享缓存写模型配置。框架对只读目录的隐式写入需要验证，必要的运行文件转入本地目录，不把该适配扩展为从机数据缓存服务。

被运行引用的缓存必须保持内容和路径可用，不能在排队或执行期间覆盖、删除。历史运行保留对应输入；本阶段不提供自动缓存或历史任务清理，不建设标注版本平台。训练缓存与可变原图、裁剪目录之间的引用必须核查，不能仅凭目录名或指纹就宣称输入稳定。

## Initial weights and training configuration

所有训练始终使用仓库现有规则下载的默认初始权重，不使用用户此前训练产物，也不使用未来管理员维护的模型作为训练初始权重。已有默认权重缓存可以复用；这不是每次重新下载。管理员模型的后续用途是生成预标注，与训练初始化分离。

训练模型版本、规模和参数沿用仓库现有定义，由业务任务关联训练配置；用户只选择目标模型，不填写 epoch、batch size 或底层参数。不因平台接入额外维护一套不同默认值。当前训练核心在 `src/xxtrain/training/workflow.py` 合并默认值与 Scenario 参数，在 `src/xxtrain/training/model.py` 准备默认权重；接口调整保留本地 Scenario 使用方式。

## User pages

现场工作区与训练任务是不同语义，分别提供独立页面，不把任务列表放在标注页面下方。本阶段沿用默认单用户、单 Point 任务与单现场，不提前建设用户管理；任务查询仍按当前用户归属限定，为跨现场汇总保留明确归属。

工作区提交成功后显示气泡“已加入训练队列”，不强制跳页，方便继续提交其他模型。已提交模型的训练按钮展示排队中、训练中、训练完成、失败或已取消；鼠标悬停时显示“查看训练任务”，点击进入训练任务页并定位对应任务。已存在的任务入口不因暂时无法查询状态而变成再次提交入口。

“我的训练任务”页面汇总当前用户的训练运行，展示现场、模型、提交时间、状态、进度、耗时、主要结果指标和产物操作，支持查看结果、下载和取消。任务页不提供重新训练入口。

训练机的在线状态、资源占用、当前任务及队列管理使用 ClearML 原生 Workers / Queues 页面，供管理员使用。普通用户不进入 ClearML 后台；本阶段不开发自建训练机页面或远程调整 Agent 数量。

## Workspace release and state derivation

只要工作区存在排队或执行中的任务，上传和所有步骤的标注按钮都禁用，禁止查看和编辑标注；后端同样拒绝相关权威数据写入，不能仅靠按钮变灰保护输入。已打开的 CVAT 页面不构成平台接受修改的授权。本阶段不要求为了此限制继续改造 CVAT 源码。

编辑锁定不阻止提交其他已经满足门禁且尚未提交的模型。只有最后一个未结束任务实际完成、失败或取消后，工作区才自动恢复上传和标注；不要求下载结果、点击确认或手动释放。取消请求发出不等于执行已停止，运行任务必须确认实际终止后才能释放限制。取消不删除图片、标注、历史任务或已经形成的结果记录。

编辑资格与结果入口分别派生。解锁后，对应训练输入发生变化、满足门禁且没有该输入的既有运行时，模型按钮恢复“开始训练”；输入未变化时保留已有任务入口。历史任务不会因后续标注变化消失。按钮依据当前相关输入指纹与运行关联，不受管理员模型版本变化影响。

最重要的状态规则仍是每次读取或动作完成后从事实重新判断。标注计数、步骤资格与缓存输入从 SQLite 图片和标注事实计算；排队、执行和结束状态从 ClearML 获取；工作区是否可编辑由关联任务的未结束集合派生。不在标注数据库存当前阶段、运行状态副本、标签有效性或累计计数，不通过加一减一推进状态。

平台在标注库之外持久保存必要的训练关联事实：运行身份、用户、工作区、目标、提交时间、输入指纹和缓存引用、ClearML 任务 ID。这些记录支持历史查询、刷新和进程重启，不是自建调度器。提交关联必须支持辨认同一次请求，外部提交结果不明时不能盲目再建任务；具体接口与持久化组织在实施计划中落实。

ClearML 暂时不可访问时显示状态查询失败，不把未知状态推断成结束、成功或取消，不提前解锁。平台返回可理解的失败信息，不把服务令牌、内部文件路径或第三方原始异常暴露给普通用户。提交、查看、取消和下载均校验任务用户归属。

## Progress and deliverables

页面展示真实上报的当前 epoch、总 epoch 与耗时，不估算尚未执行阶段的百分比；每个模型只显示一个主要验证指标，缺失时显示“暂无”，不能填零。检测和分割的指标不是准确率，统一注明“本次验证集结果”，不建设权威固定评测集。

| Point 目标 | 主要指标 | 用户下载内容 |
|---|---|---|
| 检测 | 检测效果：mAP50-95，以百分比展示 | 优化后的 ONNX |
| 分类 | 分类准确率：Top-1，以百分比展示 | ONNX、labels.txt、每个类别一张参考图，打包下载 |
| 指针分割 | 指针分割效果：Mask mAP50-95，以百分比展示 | 优化后的 ONNX |

主要指标的选择与名称、导出内容规则属于业务任务定义，与模型步骤、标注方式等定义在一起。页面、提交接口和 ClearML 适配不硬编码 Point 下载清单。检测与分割只有一个类，不提供多余 labels.txt；分类的 labels.txt 顺序必须与模型实际输出类别索引一致，参考图也按该索引关联，不能直接复制可能顺序不同的标签文件。

用户只下载导出且优化后的部署产物，不提供 best.pt 或其他 checkpoint 下载。沿用 `src/xxtrain/training/exporting.py` 的 ONNX `simplify=True` 与分类参考图能力，补齐分类标签文件与产物打包；不增加量化或硬件专用优化。运行内部可以保留 checkpoint 供现有导出流程使用，但不能作为后续任务初始权重。

训练、导出、优化和产物发布属于同一次任务；产物完整可用后才报告整体完成并提供下载。导出或上传失败不能显示为可下载的训练成功。结果指标应对应实际交付模型，不能把最后一轮指标无条件作为最佳 checkpoint 的结果。Agent 通过 ClearML 回传结果；平台提供当前用户有权访问的下载入口。

## Deferred scope

- 开源 GPU 切分及向多个 Agent 分配资源作为独立后置方向。ClearML 动态 GPU 分配和动态切片有 Enterprise 限制，开源显存限制容器不等于自动并发调度；本阶段不引入付费调度、Kubernetes 或训练 services-mode。
- 用户级未结束任务配额后置，不提前填一个默认上限；未来不以工作区数量代替用户配额。
- 管理员角色、已有标注导入、审核和并入基准库、模型管理与预标注后置。没有基准库或管理员模型不阻塞本阶段训练，当前输入只来自用户工作区。
- 自建训练机管理页面、公网入口、网盘备份、从机本地数据缓存按各自独立需求推进；不建设自动模型 DAG、数据版本平台或训练参数编辑器。

## Alternatives considered

**克隆 ClearML 模板任务。** 虽能复用后台配置，但需要额外维护模板并防止与仓库训练定义脱节；直接提交明确的训练入口和配置更符合现有代码所有权。

**整个工作区只允许一个训练任务。** 输入保护不要求阻止其他已完成标注的模型入队。等待前一个训练完成会延长现场人员操作时间，因此限制编辑而不限制跨模型连续提交。

**一开始部署多个 Agent 或动态 GPU 调度。** 当前采用单 Agent 串行执行以保持部署简单；资源切分与多 Agent 并发另行验证，不把 GPU 利用率低解释为显存和计算资源必然足够。

**把任务列表追加到工作区或自建训练机页。** 用户训练历史与标注工作区职责不同，需要独立任务页面；机器与队列运维已有 ClearML 原生页面，本阶段不重复开发。

**用户确认或下载后才解锁。** 任务实际结束已经足以解除输入保护，人工确认不能提高安全性。结果入口与编辑资格分开派生，避免自动解锁丢失历史入口。

**展示整组训练术语并提供 checkpoint 下载。** 普通用户需要可理解的单个主要指标和可部署模型，下载内容由业务任务定义，不暴露供开发调试使用的权重。

## Acceptance criteria

- 离线测试通过真实平台入口覆盖连续提交三个目标、同次请求去重、刷新和重启后的关联恢复、用户归属、队列查询失败、取消和任务结束后的解锁。
- 标注门禁和按钮状态从事实重新计算；活动任务存在时上传与标注写入受阻，但其他合格目标可以入队；输入改变、历史查询和重复提交行为符合唯一输入提案。
- Agent 消费已生成缓存，以独立可写目录调用真实训练核心；默认权重和参数不漂移，任何目标不从历史产物初始化。共享输入不被写入或删除。
- 三个目标各上报一个与交付模型相符的主要指标；导出失败不误报成功，检测和分割下载仅含 ONNX，分类打包的标签顺序和参考图与模型输出一致。
- 真实验收覆盖三个模型依次排队执行、页面进度与结果、模型下载及产物检查，并分别验证排队取消和运行取消。离线模拟不替代 Agent 在 GPU 上实际执行的证据。
- 真实服务启停与部署在授权验收范围内进行，结束后停用本次启动的服务并保持禁止自启，保留用户数据与现有测试凭据。本设计提交本身不启动远程服务。

## Risks

单 Agent 无法充分利用所有小模型场景的 GPU 吞吐，仓库固定训练参数也可能超过某台机器显存；本阶段如实报告失败，不自动改参数或并发额度。任务无配额且缓存、历史不自动清理，会积累排队任务和磁盘用量。ClearML 中断会暂时阻止安全解锁，需要恢复服务或管理员核实执行情况，不能靠本地状态猜测。共享路径、框架隐式写入、分类类别排序、模型指标归属及取消后进程退出均需真实运行验证。

本文使用独立预算保留已批准的用户流程、状态规则和后置约束；不能为了字数目标删去这些决定。真实 GPU 验收尚未实施。

## Implementation progress

取消协调、只读查询及执行结束与产物可用性分离由[训练意图协调与 CVAT 准备简化](../simplification/2026-09-18-authoritative-state-coordination.md)部分替代。相关修正已有离线实现与联合回归，真实 ClearML、Agent、GPU 和 CVAT 验收仍未完成；训练默认值、交付内容和真实验收要求保持有效。

训练核心已提供已准备数据集入口和部署交付打包。入口在每个本地运行目录复制标签和图片，防止 Ultralytics 图片修复或 cache 写入到达只读发布树；这个一次性隔离会增加每次运行的传输和磁盘用量，但不建立持久从机缓存。训练使用仓库既有默认权重和参数，从实际 best checkpoint 验证并导出固定 `model.onnx`。分类 ZIP 要求模型输出索引从零开始连续，再按该索引还原索引目录中的业务标签，并要求每个输出类别都有参考图。

`TrainingRunStore` 已在调用者指定的平台元数据路径创建独立的 `training-runs.db`。该单表只保存运行 UUID、用户与工作区归属、目标、输入指纹、相对缓存路径、提交时间、创建尝试时间和唯一 ClearML 任务 ID；它不保存执行状态、阶段或计数，也不使用 `annotations.db` 或可丢弃的 CVAT `jobs.json`。运行查询按用户归属限制，同一用户、工作区、目标和指纹只返回一条规范记录，任务绑定只接受相同事实；SQLite 写入事务串行化并发创建。`TrainingRunView`、`ExecutionView` 和 `DownloadFile` 只提供任务页面所需的数据合同，不执行 ClearML 操作。

`TrainingService` 已在 `AnnotationService` 的同一个非递归写互斥内计算当前指纹并查询用户、工作区和目标的规范运行。已有运行按当前事实投影；没有运行时才重新计算资格、生成或复用缓存，并保存带 `execute` 意图的服务端 UUID。提交、取消和应用生命周期共用协调入口执行创建、精确查找、绑定、入队或停止；列表、详情和工作区读取不执行这些操作。创建返回不明时按该 UUID 核实，已记录尝试但仍找不到远端任务时拒绝自动重建；入队返回不明的重试只使用已绑定任务。终态任务不会重新创建或入队。工作区编辑限制遍历全部关联运行并实时查询 ClearML；未知状态和未确认的创建仍视为活动，只有最后一个运行确认结束后才解锁。完成执行不依赖部署产物存在，缺少产物时解除编辑限制但禁止下载。上传、开始标注和同步均调用可选服务端保护，缓存准备与其他合格目标提交继续共用互斥但不受编辑保护拒绝。当前标注变化创建另一输入运行，恢复旧指纹返回原运行，原输入发布保持不变，已有运行引用的损坏缓存不会就地重建。

平台 HTTP 入口按当前 CVAT 会话用户限定训练提交、列表、详情、取消和部署产物下载。写请求沿用同源与 CSRF 校验，提交只接受空对象并由服务端生成运行 UUID；响应只投影现场、目标、提交时间和执行摘要，不返回缓存路径、ClearML 内部任务身份或后端异常。未知运行与其他用户运行返回相同拒绝。SQLite BUSY/LOCKED、工作区写互斥和训练期间编辑限制统一为类型化冲突；训练及标注写入口都返回相同的安全 409，已打开的 CVAT 页面不能绕过训练编辑限制。预期的存储、文件与输入事实错误返回安全 502，其他程序错误不在 HTTP 边界笼统捕获。配置 `--training-config` 时，组合根从严格 JSON 读取项目、队列、共享缓存根、独立元数据目录、worker 脚本和 Agent 运行根，构造运行账本、ClearML 适配器和训练服务，并把实时编辑保护绑定到标注服务；省略该参数时保留仅标注启动。启动检查共享缓存包含关系、元数据与可清理运行目录隔离、worker 文件及官方环境变量中的 ClearML 密钥。

现场工作区与 `/platform/training/` 训练历史使用独立页面和共同导航。工作区从当前输入指纹投影每个目标的已有运行；服务端确认排队后显示“已加入训练队列”并留在现场，已有运行按钮在悬停或聚焦时进入相应任务。任一活动运行禁用上传和标注，但不阻止其他已满足门禁且没有当前输入运行的目标提交。页面提交空对象并在成功或失败后重新读取工作区，不生成或保存训练 UUID；读取失败保留已呈现信息但不依据旧资格启用提交。训练页通过安全 REST 投影展示状态、epoch、耗时、单个业务指标、下载和取消，不显示内部路径或 ClearML 身份，也不提供重新训练；页面可见且仍有活动运行时每五秒轮询，失败保留上一次运行信息。页面资源、Node.js DOM 行为、ASGI 路由和 wheel 内容由离线回归覆盖。离线闭环组合真实训练 HTTP、应用生命周期、服务、SQLite 运行关联、标注服务、缓存和 ClearML 适配器，在 SDK 边界控制外部状态，验证无浏览器重启接续、查询只读、取消部分失败、三目标 FIFO、输入唯一运行、原缓存保留、最后终态解锁、终态缺产物及旧 CVAT 页面回写保护。当前完整离线发现集包含 699 项；本次运行观察到一项因未配置真实浏览器环境而预期跳过，其余测试进程成功退出。普通单 Agent 通过 `CLEARML_AGENT_SKIP_PIP_VENV_INSTALL` 选择预装当前 wheel、ClearML SDK 和训练依赖的受控解释器；ClearML Agent 3.0.3 源码和隔离安装 smoke 覆盖该路径，凭据保持外部提供。目标训练机的 Agent 安装、真实布局和 ClearML 服务仍需人工验收，因此本 Note 保持 proposed。

`RuntimeCache.cache_path` 仅返回完整的已发布目标目录：检测、分类和分割都需要数据集元数据、训练和验证列表以及仍在缓存发布目录内的输入文件，分类和分割还需要精确 manifest。缓存根、发布目录、目标目录、拆分列表和列出的输入文件按解析后的路径限制在缓存根内；检测发布目录中的输入图片可继续使用解析后仍在发布目录内的相对符号链接。所有缓存重建入口在替换不完整发布前检查训练关联，任何当前或历史运行引用都会拒绝重建；其他目标仍可独立准备。真实 GPU 验收仍未完成，因此本 Note 保持 proposed。

ClearML 适配固定使用 SDK 1.18.0，并在普通模块导入时不初始化 SDK 任务或服务连接。平台使用 `Task.create` 直接创建任务，以完整运行 UUID 作为初始任务名，通过项目和锚定名称精确恢复关联；创建不自动重试，入队固定使用配置队列且只接受远端 `created` 状态。Agent 执行已安装 wheel 中的 worker 入口，从受限共享相对路径读取缓存，在独立运行目录调用训练核心，禁用 Ultralytics 自动 ClearML 集成，并在固定 `deployment` 产物同步上传后才标记完成。下载仅解析该固定产物、核对项目归属并复制到平台私有目录。

运行取消使用 SDK 的 `Task.stop_request`。排队取消只在 `Task.dequeue` 明确返回已移除后写入版本化的远端任务参数，再把任务停止；只有停止状态、该参数存在且任务从未记录执行 Worker 时才释放，刷新、重试和进程重启从相同远端事实得到相同结果。参数写入失败不会停止任务，出队竞争失败也不会强制改状态。ClearML 1.18.0 的任务记录提供最后执行 Worker，workers 2.20 `GetAllRequest(last_seen=None)` 提供 Worker ID、当前任务和最后成功上报时间。运行任务只有在服务端状态为 `stopped`，同一 Worker 的记录仍存在，其成功上报时间不早于停止状态变更，并且当前任务已不同，才报告取消完成。Worker 身份缺失、记录缺失、上报过期、查询失败或仍持有任务时返回活动的 `unknown`，不会据此释放工作区。页面和平台服务编排已有离线实现；真实 ClearML Server、Agent 和 GPU 训练仍未验收，因此本 Note 保持 proposed。
