# Agent Note: Point 分类与指针分割闭环

Status: proposed

## Problem

Point 检测入口和 SQLite 权威标注已经可用，但用户不能在平台完成后续分类和指针分割的数据准备。两者都使用检测框裁剪图；分别建设裁剪、来源关联、CVAT 任务和回收流程会产生重复实现，也可能让编辑图片与训练图片不一致。

## Proposal

让用户在现有检测标注基础上，完成 Point 分类和指针分割标注，并分别生成可用的训练缓存，打通三个模型的数据准备闭环。分类和分割作为同一阶段交付，实施时先贯通分类，再接分割并联合验收；不拆成两个独立开发周期。

本文细化并部分替代[平台总体提案](2026-07-30-self-service-training-platform.md)中的下游原图编辑、分割位置匹配、各模型独立数量门槛和分阶段交付约定，以及 [SQLite 设计](../../implemented/architecture/2026-09-16-sqlite-annotation-storage.md#deferred-model-and-baseline-workflow)中的后续交付顺序。SQLite 三表、稳定对象身份、事务、步骤依赖和对象级下游清除继续有效；[部署与存储提案](2026-09-14-platform-dataset-storage.md)继续拥有部署、去重、工作区与基准库隔离方向。这些记录均部分保留，不归档。

范围包含现有页面上两个目标的开放、裁剪编辑、回收保存、进度和按钮派生、训练缓存生成及检测回归。不增加模型推理、真实训练、ClearML 接入、管理员、基准库维护、存量导入、旋转裁剪、历史版本或图片浏览页面。沿用默认用户、Point 任务和现场上下文。管理员数据治理仍在 Point 三模型闭环稳定之后。

## Shared flow and ownership

抽取“从上游标注生成编辑样本”的窄范围公共能力：第一步使用原图，后续使用关联上游对象的裁剪图。公共流程不写死 Point 或分类、分割类型，只实现当前任务需要的行为；不建设任意流程图、插件注册、调度引擎、复杂配置语言或自动模型 DAG。OCR 的旋转文本框可在真实需求出现时扩展裁剪和坐标变换，不属于本次能力承诺。

| 所有者 | 职责 |
|---|---|
| 业务任务定义 | 标签、标注类型、步骤依赖、完成条件和训练转换规则 |
| 工作区数据层 | SQLite 权威读写、对象关联和受影响下游清除 |
| 裁剪缓存 | 统一裁剪边界、生成与复用图片、提供来源对象关联和坐标变换 |
| CVAT 适配 | 类型化标签配置、图片及当前步骤标注交换、服务端对象身份，不判断训练资格 |
| 平台服务与页面 | 协调操作、派生进度与按钮、显示问题及修正入口 |
| 训练缓存生成 | 消费统一裁剪结果，组织分类数据和 line 转换后的分割数据 |

这些职责沿用现有逻辑组件，不增加服务或要求创建空包。不同标注类型保留自己的编解码与校验，共用任务准备、来源映射和回收编排，不复制两套完整流程。

## Authoritative annotations and associations

SQLite 只保存原始标注事实及其身份、步骤和对象关系。分类保存独立类别记录，指针保存原始两点 line；所有几何使用原图坐标。回收时的坐标还原是坐标系转换，不是训练格式转换。只有生成训练缓存时才进行 line 转 mask、YOLO 归一化或分类目录组织；不得把这些派生结果回写为权威标注。

每个检测框对应一个裁剪编辑样本。分类记录和每条指针 line 的 `parent_id` 都直接指向该检测框 UUID；每条 line 保持独立对象身份。同一裁剪图允许多条指针，但只能有一个分类类别。步骤依赖为检测、分类、分割依次推进，不要求 `parent_id` 链深度等于步骤顺序。

永久关系由 SQLite 的显式字段保存。Job 运行映射在运行目录落盘，记录 Job、frame、原图 ID、来源框 UUID 及实际坐标变换；不得仅留在进程内存，不靠文件名解析、几何相等或坐标匹配猜测来源。CVAT 原生对象 ID 与平台 UUID 仍由已有映射表管理，不能把 frame 到来源框的关系混同为标注对象身份。

临时图片路径和裁剪变换不进入权威标注，不为 Job 帧映射新增权威表。重启后加载运行映射继续回收；映射丢失后不能直接回写旧 Job，只能依据 SQLite 当前标注重新创建。已回收标注不受运行目录删除影响，尚在旧 CVAT Job 的未回收修改不能宣称已被平台保存。

## Crop reuse and cache inputs

分类编辑、分割编辑和训练缓存必须共用裁剪逻辑与实际裁剪结果，保证图片范围、坐标变换及训练输入一致。裁剪文件按需生成，有对应缓存则复用，缺失则重建；不建设独立缓存管理系统。图片仍是可丢弃运行产物，不按模型复制为多个权威数据集，也不要求备份裁剪图。

裁剪内容依据原图、来源框几何和实际裁剪参数确定，不因分类类别、指针 line 或模型版本变化而重裁。关联仍使用来源框 UUID，即使几何相同也不能合并两个业务对象。框几何变化后使用新的裁剪结果；类别或 line 变化只影响相应标注与训练输入，不使裁剪图片失效。

训练缓存根据各目标实际使用的图片和标注内容判断复用，不能把裁剪缓存命中等同于训练缓存有效。模型版本不进入输入指纹；标注未重新生成或修改时，模型更新不得改变指纹。缓存发布后的图片路径必须可解析，不能指向重命名之前的构建目录。

## CVAT editing

每个步骤使用独立 CVAT Task 和 Job，只展示和写入当前目标标注。使用独立 Task 的标签定义即可，不为配置标签引入 Project。检测标签指定 `rectangle`，分类的 `tl/tc/cl/cc` 指定 `tag`，指针标签指定 `polyline`。指针延续现有 Point 输入标签 `1` 及两点线段转换语义；SQLite 中的分割步骤应表达 line，而不是把现有空标签集的 polygon 占位当成正式要求。

不新增 CVAT 源码修改、点数预设注入、工具栏定制或只读上游显示。沿用现有导航隐藏和保存返回能力，用户在原生 polyline 绘制设置中选择两点。标签类型限制不能替代业务数量校验：回收时检查分类唯一性和每条 line 恰好两点；发现不合法内容时显示对应裁剪图及原因，允许返回修正，不静默丢弃、多选一或截断线段。缺少标注是可保存的未完成工作，不等同于传输失败。违反原始标注结构规则的结果不得覆盖已有合法权威数据，用户修改仍保留在 CVAT 中供修正。

在 CVAT 点击“完成”表示保存并返回，不保证平台回收成功或所有样本合格。保留现有登录、权限分配、保存失败反馈和同步重试行为；回收结果必须属于当前可接收的 Job，浏览器不能指定任意数据库对象或文件路径。

源码核查确认验收版本的 `Label.type` 支持 `rectangle/tag/polyline`，标签归属于 Project 或 Task，Job 使用所属任务标签。绘制弹窗的 `numberOfPoints` 与矩形绘制方式属于前端绘制设置，不是标签 schema。类型限制、图片级分类、多条两点 line 及返回行为仍需真实 CVAT 验收，源码核查不构成这些功能已交付的证据。

## State derivation and user flow

最重要的状态约束是从事实重新判断，而不是根据动作推进枚举。每次读取及上传、标注回收、缓存生成结束后，按步骤依赖顺序，从 SQLite 当前图片和标注及运行产物重新计算完整性、计数和按钮；不保存当前阶段、标签有效状态、完成标记或累计计数，不执行加一减一。操作期间沿用串行写入与页面互斥，不增加后台状态机。

| 步骤 | 计数单位与完成条件 | 开放能力 |
|---|---|---|
| 检测 | 原图；全部已标注，且至少 50 张有框原图；显式检测负样本计入已标注但不计入 50 张 | 检测缓存及分类标注 |
| 分类 | 裁剪图；每张恰好一个有效类别；无独立数量门槛 | 分类缓存及分割标注 |
| 指针分割 | 裁剪图；每张至少一条有效两点 line，可有多条；无独立数量门槛 | 分割缓存 |

有效原图大于零即可开始检测标注。分类、分割的开放还要求前置步骤条件成立；不能以空集合全部满足为由绕过检测门槛。只有检测允许显式有效负样本，基于框的后续模型没有负样本；检测负样本不生成裁剪图。多条 line 不增加已标注裁剪图数。50 张门槛只检查工作区检测样本，不读取基准库，也不为下游重复设置门槛。

进入下一步不要求先生成当前缓存或训练。页面保留“业务任务／现场”、顶部原图总数与上传入口、三个模型纵向排列及各自标注和训练按钮。检测展示原图进度，分类和分割展示裁剪图进度；不在顶部增加跨模型标注总数。条件不足的按钮灰显，当前“开始训练”仅生成所选模型缓存，并明确反馈缓存结果。过程提示、上传和成功气泡沿用已验收交互。

## Changes and re-entry

打开、查看或原样保存不改变标注，不清除下游，也不使训练输入失效。修改或删除检测框清除该框的分类和全部指针 line；几何变化使用新裁剪。修改分类类别按步骤依赖清除同一框的指针 line，但复用裁剪。修改 line 只影响分割标注及分割训练输入。同图其他框和其他图片的标注保持不变。

继续沿用原生 CVAT ID、稳定平台 UUID、原子标注与对象映射更新、受影响下游 Job 失效及过时回写拒绝机制。需要重建 Job 时从 SQLite 带入当前步骤仍保留的标注，不要求全部重标；不做历史标注快照、按坐标猜测身份或保存标签有效性字段。补充上传或上游修改导致条件变化时，三个步骤从当前事实重新计算，下游入口不得沿用旧计数开放。

## Implementation status

共享编辑契约现已定义不可变的 annotation、frame mapping、frame result、Job 和目标计数记录；`JobRef.sample_ids` 仍表示去重后的原图 ID，frame mapping 单独保存原图 ID、来源框 UUID 和实际整数边界。Point 业务规则接受空的分类或分割编辑作为未完成工作，要求分类至多一个 `tl/tc/cl/cc`，并要求每条 `1` polyline 恰好包含两个有限且不同的点。Point 分割步骤现声明 `polyline` 和标签 `1`，分类与每条 line 仍直接关联检测框；通用任务定义继续支持 polygon。

离线测试覆盖不可变记录、分类数量与类型校验、line 点数、有限值和零长度校验，以及分类和原始 line 几何通过真实 SQLite repository 保存并重开后的往返。

共享裁剪按原图 SHA、实际整数边界和 RGB PNG 编码策略复用可丢弃文件；边界使用向外取整并限制在原图范围内，frame 保留来源框 UUID，坐标转换使用实际整数原点。缺失文件从原图重建，框类别和下游标注不参与裁剪键。运行目录的 Job 条目可选保存有序 frame mapping，记录原图 ID、来源框 UUID 和实际边界；加载时校验 frame 身份、原图引用、边界和 `JobRef` 的有序唯一原图集合，缺少 mapping 的旧检测条目仍可读取且不能被当作编辑 Job。目标失效同时清除普通和编辑 Job 的全部历史指纹。

CVAT 交换现支持类型化任务标签、分类 tag 和指针 polyline。初始化通过保留属性携带临时 UUID，完整校验 token、frame 和 `(object_type, native_id)` 后建立原图 ID 下的绑定；常规回收只返回 CVAT 原生 ID，不采用复制的初始化 token 作为编辑身份。分类与 polyline 使用 `EditJob.frames` 的精确顺序和来源映射，`JobRef.sample_ids` 仍只保存首次出现顺序下的唯一原图 ID。检测与编辑任务共用上传、轮询、frame 核对、Job 分配、初始化和指派流程，检测创建接口继续生成 rectangle 标签。

`WorkspaceData` 从当前检测框和目标记录投影分类或分割 frame，分类几何保持为空，line 使用实际裁剪原点转换为局部坐标。目标摘要直接从数据库计算裁剪数与完成数；目标指纹包含原图身份、检测框 UUID 和内容、目标记录以及分割所依赖的分类关联，不包含运行路径或模型元数据。回收要求 Job mapping 与当前来源框 UUID、原图和实际边界完全一致，并要求结果完整覆盖 frame；原生 `(object_type, native_id)` 只能复用同一原图、步骤和父框上的稳定 UUID。新增对象获得 UUID，省略对象只删除当前目标记录，分类内容变化通过既有变更规划清除同一框的 line。标注和 CVAT 映射继续由 repository 在同一事务提交，返回的指纹从计划后的最终记录计算。

离线测试使用真实彩色图片验证边界裁剪、像素和坐标往返、同几何不同 UUID 的独立映射及文件复用、几何变化、删除重建、尺寸不符和空裁剪失败，并通过磁盘重开验证编辑 Job 映射及错误数据拒绝。CVAT codec 和受控 HTTP 客户端测试覆盖 tag 与 polyline 往返、点序、类型与传输几何拒绝、初始化 token 完整性和错帧、tag 与 shape 可复用同一数值 ID、裁剪上传核对、绑定及回收；数据层测试覆盖双框、多 line、本地坐标、复制、无修改、删除、同图跨 frame 拒绝、重启绑定恢复、事务回滚、局部完成计数和输入指纹。联合回归通过正式 HTTPX CVAT 适配器、平台服务、SQLite 数据层和缓存构建器贯通检测、分类、分割及两个下游缓存，逐项固定无修改、父框变化、改类、多指针新增、复制和删除、旧 Job、重启、缓存可读性，以及同一原图兄弟框及其分类、指针和绑定的精确不变。原始坐标记录和 CVAT 原生绑定使用明确期望值断言；映射插入触发器在标注写入后中断真实 SQLite 事务，验证标注与绑定共同回滚并可在重启后重试。每条 line 恰好两点和分类唯一性仍由业务规则负责。

下游训练缓存直接读取目标投影已物化的共享 PNG；分类通过现有 indexed class 目录及 224 像素 letterbox sink 输出，指针分割通过现有 `EncodePointSegment` 把每条两点 line 编码为 class 0 的三角形。分割图片作为普通文件复制到发布目录，删除可丢弃裁剪缓存不影响已发布输入。完整构建先在同级临时目录写入并改写最终路径，再以目录替换发布；发布根目录的 `manifest.json` 仅包含精确的 `fingerprint` 和 `target`，运行缓存同时验证该对象和对应目标目录。格式错误、字段不匹配或目录缺失都视为缓存未命中。生成过程不修改 SQLite，越界三角形不发布缓存。

数据库 schema 仍保持三张表。`MODEL_TARGETS` 已开放分类和分割；平台服务从实际原图、裁剪标注及缓存产物派生三个目标的计数和操作资格，共用带写锁的开始、同步和缓存分派。严格 HTTP 目标路由保留原检测端点，页面按三行显示原图或裁剪图进度，并以每标签页 allowlisted 提示选择返回同步目标；服务端仍只接受运行目录中的当前 Job 和 frame 映射。无效分类数量或指针 line 结构不覆盖已有标注，页面保留待同步状态并链接到当前 Job 的问题帧。离线真实组件、HTTP 与 Node 页面测试覆盖门槛重算、负样本排除、无缓存步骤推进、重启复用、完成 Job 修正、身份同步、缓存发布、鉴权与 CSRF、返回提示和逐行忙碌状态。真实浏览器 harness 只接受新建的 50 张原图、51 个框三步骤 fixture；检测无修改往返、分类改类、两点 polyline 绘制和合法修正均使用 CVAT 原生控件及返回插件的“完成”按钮，REST 写入只构造重复 tag 和三点 polyline 两种非法输入。CVAT 2.51.0 源码核查固定控件选择器与侧栏默认排序，但同版本服务尚未获授权运行，因此原生身份、裁剪 frame 来源、结构错误修正、返回目标和缓存可读性的现场证据仍是明确缺口，本 Note 保持 proposed。

## Alternatives considered

**分类、分割各建完整流程并分两次交付。** 两者的裁剪、来源映射、任务准备和同步相同；分别建设会重复改接口。保留标注类型差异，在同阶段内依次贯通并联合验证更直接。

**通用多模型工作流框架。** 检测后裁剪的业务规律支持公共能力，但不要求任意 DAG、调度引擎、插件系统或复杂配置。旋转裁剪和 OCR 特有标注规则等真实需求出现后再扩展。

**每次重复裁剪，或各模型使用不同裁剪实现。** 单次实现简单，但重复处理且容易出现编辑与训练边界不一致；统一逻辑和按需文件复用不需要复杂生命周期管理。

**通过文件名或权威标注里的临时路径恢复来源。** 名称解析把持久关系绑定到可丢弃文件布局，临时路径也不应进入权威标注。数据库保存永久父关系，运行映射保存编辑 frame 来源及坐标变换。

**直接画 mask 或在 SQLite 保存训练 mask。** Point 的两点 line 已用于现有转换，减少人工标注难度；原始 line 保留可重新转换的事实，训练编码仅属于生成产物。

**为每个后续模型再设 50 张门槛。** 检测门槛已经约束进入后续步骤的原图来源；下游只需全部裁剪图完成标注，重复门槛没有独立业务收益。

**修改 CVAT 自动预设两点或锁定上游。** 点数不是 Task 标签参数，前端适配会增加维护范围。本次采用原生类型约束、人工点数选择和回收校验，不新增 CVAT 定制。

## Acceptance criteria

- 用户从平台分别进入分类及指针编辑，完成后返回；分类仅图片级类别，指针仅当前步骤 line；检测交互不退化。
- 同一原图多个框、同几何不同 UUID 的框以及同框多条 line 均准确关联；服务重启仍可按落盘 Job 映射回收，不通过坐标或文件名推测来源。
- 分类恰好一个类别、分割至少一条两点 line；多类别或错误点数提供定位与原因，不产生静默截断或权威数据损失；空裁剪不被当作负样本。
- 检测 49／50 张及显式负样本计数保持原门槛；下游只校验全部完成，缺少前置条件时禁用，缓存生成不是下一步前置条件。
- 裁剪图片在分类、分割和训练中一致；line 原图与裁剪坐标往返正确；同图多框、多指针、边界裁剪和重复生成均有覆盖。
- 分类缓存能由现有分类数据读取流程消费；分割缓存保持现有两点 line 转三角形分割标签语义，包含每条指针；发布后的路径可读取，SQLite 不含训练编码结果。
- 无修改回收保持身份及下游；单框修改、分类修改和 line 修改只影响规定范围；旧 Job 拒绝回写，重建带回其他仍有效标注；事务失败和重试保持原子性。
- 页面计数及按钮在上传、同步、重启和缓存生成后均由事实重算；裁剪可复用不等于训练缓存可复用；模型版本不影响指纹。
- 完成离线测试和同版本真实 CVAT 三步骤验收；真实服务部署另需授权，验收后停用临时服务并保留用户数据，不启动真实训练或 ClearML。

## Risks

CVAT 原生标签类型不保证单分类或固定两点；用户可能需要回到问题帧修正，平台不得把 Job completed 当作训练资格。源码检查尚不证明新增类型的实际编辑与原生 ID 往返，必须通过现场验收。

裁剪舍入、边界处理和坐标变换若不一致，会把正确标注转换到错误位置；共用实际裁剪结果并验证往返是必要约束。运行映射丢失可能留下无法直接回收的旧 Job；SQLite 中已保存标签仍可重建，不承诺恢复未回收编辑。

分类变化按既定依赖清除对应指针，可能需要重画该框的 line；保留其他框数据降低影响，不增加有效性状态或历史恢复系统。缓存是可丢弃产物，磁盘占用及清理不能以破坏当前训练缓存的图片引用为代价。
