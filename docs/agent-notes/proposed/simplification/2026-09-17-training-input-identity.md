# Agent Note: 按训练输入唯一提交

Status: proposed

## Problem

用户需要在训练输入变化后提交训练，输入未变化时查看已有任务。同一缓存重复训练不属于平台能力。浏览器维护请求 UUID、提交确认和编号清理规则，会把同一业务操作拆成跨页面的恢复流程；刷新、重新登录或请求失败不应改变任务身份或产生额外训练。

## Proposal

每个用户、工作区、目标模型和训练输入指纹的组合只对应一条训练运行记录。用户提交后，无论刷新、重新登录还是遇到请求失败，都从权威记录重新得到结果，不依赖页面保存操作历史，不因重试创建重复任务。

本文部分替代 [Point 自助训练与结果交付](../feature/2026-09-17-point-training-loop.md) 中的请求身份、同缓存重新训练及对应按钮规则。该提案继续拥有排队、训练默认值、编辑保护、取消实停、进度、产物和部署验收。输入唯一存储、服务提交、HTTP 和页面行为已有离线实现；真实 ClearML/GPU 验收仍未完成，因此本文保持 proposed。

## Implementation progress

训练运行存储按用户、工作区、目标和指纹建立唯一索引。创建相同输入时返回已保存的运行及其创建尝试和 ClearML 关联；缓存引用或既有 UUID 事实冲突时拒绝写入。旧数据库启动时先检查重复输入：无重复的数据保留原有事实并获得索引，有重复的数据报告具体组合并保持全部记录不变。服务在标注互斥内查询该索引，HTTP 只接受空对象，浏览器不保存训练请求身份；历史重训入口已删除。离线联合回归通过真实 HTTP、服务、运行存储、标注服务和缓存覆盖连续提交、并发唯一性、重启、取消确认、未知状态、最后终态解锁、旧页面写入拒绝及输入恢复；仅 ClearML 外部状态和 CVAT 会话受控。

## Authorities and identity

- 工作区图片与 SQLite 标注事实决定当前目标的训练输入指纹及标注资格。复用现有目标指纹，不以缓存目录名、生成时间、重复生成操作或管理员模型版本表示输入变化。
- 平台训练关联 SQLite 保存运行身份、用户与工作区归属、目标、输入指纹、缓存引用及 ClearML 任务关联；以用户、工作区、目标和指纹组合保证唯一，不保存业务阶段、执行状态副本或累计计数。
- ClearML 是排队、执行、结果及产物事实的权威来源。平台运行 ID 与 ClearML 任务 ID 是关联标识，不是两套状态。
- 浏览器只提交操作并展示服务端重新计算的结果，不生成或持久保存训练请求 UUID，不维护提交、确认、回退等业务阶段。请求进行中的按钮禁用、错误提示及页面刷新不构成持久业务状态。

## Submission and page behavior

每次查询和用户操作后，后端重新读取输入事实、运行关联和 ClearML，计算按钮、任务摘要及编辑权限，不根据上一次页面显示推进或回退状态。

当前输入存在关联运行时，模型按钮只进入该任务详情。此规则不随任务排队、运行、完成、失败或取消而改变；输入变化且满足标注门禁、并且该输入没有既有运行时，才显示可提交的“开始训练”。如果输入恢复到曾经训练过的指纹，仍返回该指纹已有运行。

提交入口在服务端计算当前输入身份并查询关联：已有运行返回该运行，没有才校验资格、准备缓存并创建关联和 ClearML 任务。重复点击、并发请求、刷新或平台重启不能创建同一组合的第二条运行。运行 ID 由服务端管理，浏览器无需区分请求重发与主动重训。

删除任务页“重新训练”按钮、历史重训 API、对应服务入口及仅为它们保留的代码和测试。不提供后继运行链、重训计数或另一种创建同缓存任务的入口；取消操作和历史查看、下载保持原有职责。

操作完成或失败后，页面重新读取服务端结果。查询失败显示不可确认，不把失败解释为尚未提交，不自行恢复可提交资格；再次查询由同一组权威事实决定页面。只有确认入队才提示“已加入训练队列”。

ClearML 创建或入队返回不明时，仍使用服务端既有运行身份查询、核实并恢复同一个任务。未知不等于不存在，不因网络错误或暂时查不到任务而盲目再次创建。必要的任务关联和外部调用事实保留在后端，不要求浏览器参与恢复，也不引入自建调度器或持久业务状态机。

## Unchanged boundaries

所有活动运行继续限制工作区上传及标注写入，但不阻止其他合格目标提交；最后一个任务实际结束才解锁。查询失败不能提前解锁。输入缓存保持只读和独立发布，已有运行引用的缓存不能覆盖或删除。单 Agent 排队、初始权重、指标、ONNX 交付、用户归属、认证与 CSRF 规则不变；不启动远程服务或扩大管理员能力。

## Alternatives considered

**浏览器请求 UUID 与历史重训。** 请求级身份可以区分网络重发和用户主动重复训练，历史缓存也能支持同输入再次执行。但平台不支持同缓存重训，业务输入已经足以区分运行，保留该能力会增加前端恢复和后端接口，而没有用户收益。历史缓存仍因输入保护和任务可追溯需要保留。

**全部关联只存 ClearML。** 可以减少本地关联，但需要重新设计平台用户归属、输入查询及外部创建失败恢复。本次复用独立 SQLite 关联和 ClearML 执行事实，不迁移这些职责。

**只集中现有前端恢复逻辑。** 可减少重复代码，却仍依赖浏览器记录提交过程，不能满足刷新或重新登录后直接从权威来源判断的要求。

## Acceptance criteria

- 相同用户、工作区、目标和指纹在连续点击、并发提交、刷新、重新登录及平台重启后只存在一条运行，并关联同一个 ClearML 任务。
- 已有任务无论处于何种执行结果，输入未变时均只提供详情入口；失败或取消不会开放同缓存新训练。
- 相关输入变化且门禁满足时可以创建新运行，旧记录保留；恢复旧指纹时返回旧运行。重复生成同内容缓存不创建新运行。
- 提交接口不依赖浏览器请求 UUID，页面不持久保存提交阶段；HTTP、真实服务及包内页面脚本共同覆盖上述行为。
- 历史重训按钮、API 和服务能力被删除，测试验证其不再可用，而不是保留未显示的兼容入口。
- 查询失败和外部创建结果不明不产生重复训练或提前解锁；恢复成功后页面从权威事实重新展示结果。
- 三目标连续提交、旧 CVAT 页面回写保护、排队和运行取消、产物下载及用户归属回归保持有效。真实 ClearML/GPU 验收仍按原提案执行，离线测试不替代真实证据。

## Risks

同一输入的任务失败或取消后，用户不能在平台创建替代训练；这是不支持同缓存重训的明确限制，而不是待补的重试功能。恢复外部提交与重新执行终态任务必须区分，恢复不能复活已结束任务。

输入身份依赖现有目标指纹的正确性；本次不重新发明数据集格式或业务版本号。现有开发数据库可能包含同输入多运行，实施计划必须明确处理，不能静默丢弃任务或用户数据。SQLite 唯一关联不能单独保证外部调用恰好执行一次，创建结果不明时仍需核实 ClearML；无法核实时如实报告，不用新的浏览器状态弥补。
