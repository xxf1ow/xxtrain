# Agent Note: 训练意图协调与 CVAT 准备简化

Status: proposed

## Problem

审查基线 `ade684d` 的训练查询会恢复入队，取消操作却没有持久用户意图。ClearML 排队取消在出队后可能呈现 `created`；取消后续调用失败时，查询恢复会重新入队。提交与读取拥有不同恢复分支，取消没有共用互斥。执行状态又与产物可下载性耦合，远端已完成但缺产物会继续锁住工作区。该基线的 CVAT 准备保留平台未使用的阶段检查点接口，增加了按执行历史恢复的复杂度。

## Proposal

用户提交或取消后，刷新、重试和服务重启都保持原有意图，不重复训练、不反转取消，并根据实际执行事实安全开放编辑与结果入口。本设计遵循[状态设计与权威事实规范](../../implemented/process/2026-09-18-state-design-rules.md)。

本文部分替代[训练输入唯一性](2026-09-17-training-input-identity.md)中的读取恢复机制，以及 [Point 训练闭环](../feature/2026-09-17-point-training-loop.md)中的取消协调和执行与交付合并判断。输入唯一性、用户归属、历史保留、共享输入保护、训练默认值、单 Agent 和交付内容均不改变。内部修正已有离线实现和联合回归；真实 ClearML Server、Agent、GPU、CVAT 和浏览器验收仍未完成，因此本文保持 proposed。

## Facts and intent

| 内容 | 唯一权威 | 规则 |
| --- | --- | --- |
| 图片、标注和输入资格 | 工作区文件与标注 SQLite | 从当前记录重算，不存计数或业务阶段 |
| 运行身份、用户、输入、缓存和远端关联 | 训练 SQLite | 保持同用户、工作区、目标和指纹唯一 |
| 用户期望 | 训练 SQLite 的 `desired_action` | 新运行保存 `execute`；取消保存 `cancel`，不可恢复为 `execute` |
| 创建尝试和远端请求身份 | 训练 SQLite 及 ClearML | 保留必要证据，不将尝试解释为创建成功 |
| 执行状态、进度、结果和部署产物 | ClearML | 只读观察，查询失败保持未知 |
| 按钮、编辑锁定、取消反馈 | 统一派生函数 | 由上述事实与意图计算，不持久保存 |

`desired_action` 是授权事实，不是 `submitting`、`queued` 等执行阶段。新建运行与初始意图在同一事务内保存。取消意图先提交事务，再进行外部操作；重复取消不改变身份，外部失败不撤销意图。已取消输入再次提交仍返回原运行，不改为执行、不建立替代任务。

旧 schema 的记录原样保留，仅增加可空意图列；旧行的 NULL 表示没有可证明的持久意图，不自动推断为执行或取消。旧任务继续查询、下载和按实际事实限制编辑，用户仍可明确取消。旧行不参与自动创建或入队，也不通过重复提交隐式补成执行意图；远端状态无法确认时报告需管理员核实。不得删除旧记录、丢失关联或以开发数据为由清空数据库。

## Read and command boundaries

列表、详情、工作区和下载资格查询只读，不调用创建、关联修复、入队或取消。查询可以短暂使用现有互斥取得一致的本地输入与记录，但外部观察不持有工作区写锁。读到的数据仅用于本次投影，不能代替随后写入时的重新校验。

提交在工作区互斥内重算指纹，找到既有运行则返回其身份；新输入通过资格与缓存校验后原子保存运行及执行意图。取消在相同互斥内保存取消意图。两者离开意图写入后触发同一个协调入口，不再各自实现恢复分支。

协调每条运行时取得现有工作区互斥，再重新读取意图和关联，完成该次必要外部操作；取消与协调不能交错使用过期意图。争用沿用安全冲突反馈，后台协调遇忙跳过本次，不排出另一套锁等待队列。记录取消成功后，任何后续协调都不得创建或入队该运行；已在取消落库前完成的入队通过正常取消收敛。

## Coordination lifecycle

启用训练服务时，由应用生命周期管理一个进程内协调循环；仅标注模式不启动。提交、取消命令触发一次协调；应用启动立即执行一轮，之后每轮结束等待 5 秒再执行。循环只按已有运行的提交顺序检查意图与事实，不选择训练机、不分配资源、不替代 ClearML 队列，也不增加消息服务或配置项。

每次协调都从训练 SQLite 重读，不保存待处理阶段或前进游标。线程内唤醒、停止信号和互斥只控制运行过程，不是业务事实。单次外部请求必须有有限超时；一条运行失败不吞掉诊断，也不终止其他运行的观察。应用关闭停止后续轮次，等待在途协调退出后才关闭所用资源；不能只取消异步等待而留下仍在写入的线程。进程被强制终止时由持久意图支撑下次启动，不宣称外部调用已回滚。

### Execute intent

- 没有远端关联且从未尝试创建：先保存创建尝试事实，再创建、绑定；同一运行只允许一个创建尝试进入外部接口。
- 已尝试但没有关联：用既有运行 UUID 精确查找，唯一匹配才绑定；没有匹配、歧义或查询失败不自动再建，继续报告未确认。
- 关联任务为 `created`：先从 ClearML 重读启动脚本和 `Args/*` 参数，并与该运行的 worker、输入路径和运行目录核对。任务从未执行且已有值不冲突时，协调可补齐同一任务缺失的启动事实并再次读取确认；冲突或无法确认时保持未知且不入队。只有确认完整后才向配置队列入队。已经排队或运行则不重复操作；完成、失败、停止等终态不修改启动配置或重新入队。
- 外部请求返回不明：下轮核实实际事实，不恢复到某个本地阶段。期望执行表示完成这次提交，不表示无限保持运行。

### Cancel intent

- 尚未尝试创建且没有远端关联：从本地事实即可确认没有平台启动的执行；保留取消意图和历史，不创建任务。
- 已尝试创建但关联缺失：仅查找、核实和绑定原任务，再取消；无法核实仍保持未知及编辑保护，不把“没找到”当作“未执行”。
- 远端为 `created` 且确认未执行：只终止，不入队。排队任务先出队再终止；出队后后续调用失败，下轮仍按取消意图接续。
- 正在运行：请求停止；取消请求不等于实际结束，沿用远端状态和 worker 释放证据的安全要求。
- 已结束：不重启、不清除结果；完成或失败仍如实显示其执行结果，不因后到的取消请求重写为已取消。

远端取消证明仅在确有必要证明未执行或已释放时保留；它不能代替本地取消意图，也不能成为入队授权。无法证明停止时保留未知，不能为移除复杂度而放宽实停要求。

## Projection and HTTP behavior

执行终止与部署产物可用分别计算。ClearML `completed` 不因缺产物而被改判为活动；页面说明执行已结束但产物不可用，禁止下载，不显示交付成功。产物查询失败不能抹掉已经读取到的执行终态；执行事实本身不可用时仍保持未知和必要保护。取消运行继续要求停止证据，不能仅因产物存在就解锁。

新增且尚未创建的执行意图也属于未结束工作，限制编辑；无创建尝试的取消意图可直接解除该运行造成的限制。工作区汇总和所有写入守卫共用同一判定函数，检查该工作区全部运行。不同合格目标仍可提交，最后一个未结束运行确认结束后自动解锁。

提交、取消响应分别区分意图已保存和外部效果已确认。只有确认入队才显示“已加入训练队列”；意图已保存但未确认时提示“提交已保存，等待确认”，并保持已有任务入口。取消尚未实停时提示“取消请求已保存，等待停止”。这些文案由事实派生，不增加持久页面阶段。后台会继续接续，不要求浏览器保留请求身份或重新提交。

训练、上传、标注同步及缓存响应采用同一工作区投影。把投影调用纳入各路由既有安全异常边界，互斥冲突返回 409，预期的存储或外部失败返回 502，不因响应阶段异常泄露原始 500。普通用户仍看不到 ClearML ID、内部路径、凭据或第三方异常。

## CVAT scope

删除平台未使用的 `PreparationState`、`PreparationCheckpoint` 及对应恢复参数和阶段分支。检测与编辑任务均只对本次新建 Task 顺序上传、等待请求、核对实际 frame、初始化标注、建立原生对象绑定并分配 Job；保留超时、实际响应校验、绑定完整性和成功后发布 Job 的约束。

不实现恢复任意旧 Task 的自动初始化，不根据图片已存在就断言标注可覆盖。准备失败不发布可用 Job；现有平台重试允许新建 Task，外部遗留任务可由管理员清理，本次不建设自动清理器。已发布且可复用 Job 的读取与普通标注回收不改变。测试不再把未使用的阶段恢复接口当作支持能力。

## Alternatives considered

**只给读取恢复补取消标记判断。** 仍把查询与执行混在一起，标记写入失败继续丢失用户意图，不能修复权威边界。

**只在用户再次点击时恢复。** 实现更少，但取消已被平台接受后可能长期没有后续调用。进程内小型循环接续持久意图，不让执行正确性依赖浏览器在线。

**持久化提交中、取消中等业务阶段。** 多出一套执行状态及回退规则；保存 execute/cancel 意图与必要调用事实已足够。

**把 CVAT 也改成通用期望状态工作流。** 当前没有恢复已有准备中 Task 的实际入口，删除未使用接口更直接，避免为形式统一扩大能力。

## Implementation evidence

训练账本保存可空的 `desired_action`，并原子记录所属用户的取消意图。重复创建返回原有意图，不覆盖取消；旧十列账本只增加可空列，既有事实和 NULL 意图保持不变。新运行保存 `execute`，提交、取消和周期调用共用单条运行协调路径；协调按账本提交顺序处理当前工作区，争用时跳过该运行，外部不确定性保留持久意图并记录诊断。列表、详情、工作区和下载资格只观察事实，不创建、绑定、入队或取消。待创建执行、未尝试取消、旧 NULL 运行和缺失关联分别投影；编辑守卫与工作区汇总按配置工作区的全部运行共用活动判断，按钮只显示当前用户、当前工作区和当前输入的任务，用户历史仍保留其其他工作区运行。完成执行不依赖部署产物存在，产物查询失败不覆盖已知终态，运行查询失败仍保持未知和锁定。ClearML 适配器使用独立 SDK Session，把连接、读取和写入超时限制为 3 秒连接和 10 秒读取，SSL 与内容解码最多尝试三次，并把 502/503 等服务端失败转换为上层可终止错误。首次 Session 认证失败进入相同的外部不确定性边界，单条失败不终止协调扫描；有限错误结果携带 SDK 编程异常，并在离开 SDK 无限重试层后恢复原异常及因果链。创建恢复先核对同一 `created` 任务的规范脚本和 argparse destination 参数，只补齐无冲突的缺失值，再从 ClearML 重读确认；不完整、冲突、已执行或期间取消的任务不入队，也不创建替代任务。适配器不修改进程环境，也不遗留后台请求线程。FastAPI 生命周期仅在启用训练时拥有一个协调线程，启动立即协调，每轮结束后等待 5 秒；关闭先设置停止信号并等待在途协调结束。任务 JSON 公开待确认执行状态和取消请求布尔值，不公开持久意图或 ClearML 身份；页面分别显示意图待确认、确认排队、正在运行、取消等待、终态和终态无产物。标注同步及缓存写响应的工作区投影沿用 409/502 安全异常边界。CVAT 准备接口只接受 Task 响应以整数 `0` 明确证明无图片的新建 Task；缺少、NULL、布尔值、非整数或非零 `size` 都在上传前失败。准备按上传、请求轮询、实际 frame 核对、单次标注初始化、原生绑定解码和 Job 分配的顺序执行；绑定不完整或任何更早失败都不会发布可复用 Job。120 秒期限、负样本 Tag、分类 Tag、指针 polyline 和原生对象身份保持覆盖；接口不定义阶段检查点类型、参数或恢复分支。离线测试覆盖上述 CVAT 行为。训练联合回归组合真实 HTTP、应用生命周期、服务、SQLite 账本、标注服务、缓存和 ClearML 适配器，只控制 SDK 边界与 CVAT 会话；它验证无浏览器接续执行意图、精确一次入队、查询只读、创建部分成功后的原任务恢复与取消、出队后取消部分失败与重启收敛、创建前取消、旧行观察、三目标最后终态解锁、完成但缺产物、规范历史及原缓存保留。真实 ClearML Server、Agent、GPU 和 CVAT 验收仍未完成，因此本文保持 proposed。

## Acceptance criteria

- 列表、详情、工作区和下载资格查询不触发 ClearML 写操作或训练关联写入；重复读取不会改变排队结果。
- 出队后标记或终止失败、响应丢失、进程重启，均不会让取消意图的任务再次创建或入队；尚未绑定远端任务也能保存取消意图。
- 相同输入的提交、失败、取消和终态仍只对应一个历史运行；输入恢复返回原运行。旧记录不被默认执行、删除或改绑。
- 命令和周期协调共用同一实现；无浏览器访问也能接续已保存意图；关闭应用后无遗留协调写入。单条任务失败不杀死协调循环。
- 创建结果不明不重复创建；取消与执行协调互斥，取消请求和实停仍分离；未知不提前解锁。
- `created` 任务只有在规范启动脚本和参数经远端重读确认后才入队；部分创建只补齐原任务，配置冲突、补齐中取消和终态均不覆盖或入队。
- 远端已完成而产物缺失或产物查询失败时，执行结束与下载不可用分别反映；页面和后端编辑守卫对相同事实给出相同答案。
- 所有突变响应的投影错误仍返回安全 409/502；三目标连续提交、跨用户拒绝和旧标注页回写保护保持有效。
- CVAT 准备接口不含阶段检查点，仍覆盖检测负样本、分类 Tag、指针 polyline、对象绑定、失败不发布及成功复用。
- 离线测试使用真实服务、SQLite、HTTP 和页面消费者，控制外部边界；文档和安装包检查按项目测试指南执行。真实 ClearML、GPU 和 CVAT 验收仍是单独授权步骤，本 spec 不启动远程服务。

## Risks

进程内协调增加少量持续查询；本阶段规模小，不引入任务索引缓存、通用重试策略或调度优化。5 秒是接续间隔，不是外部调用完成时限。外部服务无法确认创建结果时仍可能需要管理员核实，保守等待优于重复训练。

旧运行没有取消意图，自动回填执行会引入不安全推断；保留只读观察会牺牲旧未完成提交的自动恢复。CVAT 准备失败可能遗留未发布任务，接受管理员清理，不为消除该运维成本重新引入阶段恢复。

本文与规范使用独立文档预算，保留取消时序、迁移限制、停止证据及关闭行为，不为缩短文档删去安全边界。
