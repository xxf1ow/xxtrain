# Agent Note: 业务任务定义驱动的标注与训练

Status: proposed

## Problem

平台已有 SQLite、CVAT 和 ClearML 闭环，但公共实现仍包含 Point 步骤名、固定目标集合、顺序门槛和整工作区训练锁。Point 分类与指针分割实际都只消费检测框裁剪，分类并不是分割的数据依赖；把展示顺序当作依赖，会错误清除分割标注、改变训练输入身份并阻止互不影响的编辑。仅修改一处依赖配置不能消除存储、缓存、页面及 worker 中的独立判断。

核心价值是：新增业务任务时，只增加该任务的定义与必要业务算法，不修改既有公共实现；各组件对同一任务的关系、资格及训练输入作出一致判断。

## Proposal

以 Python 业务任务模块统一定义规则，通过配置选择加载入口。平台和训练 worker 加载同一任务定义。已有通用能力可复用，特殊算法留在任务模块，通过明确接口调用；公共代码不得按任务名称分支，也不得内置 Point 的步骤集合。

本次贯通 SQLite 访问与校验、CVAT 准备和回收、裁剪投影、训练缓存、训练协调、指标与交付、HTTP 和页面。保持现有图片、标注、账号、已发布缓存和训练历史。不引入通用工作流引擎、配置 DSL、页面创建任务、热加载、模型推理、管理员页面、存量导入或基准库治理。

## Definition and ownership

任务定义拥有下列规则，而非对应运行事实：

- 业务任务标识、步骤标识、名称与展示顺序；步骤标识不是模型类型或父链深度。
- 标注形状、类别、数量约束、合法性及完成条件，显式负样本支持和样本门槛。
- 输入使用原图还是上游对象生成的编辑样本、允许的父步骤，以及裁剪、投影和坐标转换能力。
- 实际标签依赖：父来源自动构成依赖；额外依赖仅用于确实消费其他步骤标签的算法，不重复声明父来源。
- 训练转换、初始权重与训练默认值、主要结果指标及部署交付内容。

不增加独立的流程前置字段。开放条件由实际输入可用性和所需标注完成条件派生；展示顺序不构成完成或训练依赖。进入下游不要求先训练上游，也不等待兄弟步骤训练。

| 组件 | 职责 |
|---|---|
| 任务模块 | 声明规则，组合复用能力，提供任务专用算法 |
| 工作区数据层 | 保存图片及原始标注事实、校验关系、事务更新、查询关联 |
| 编辑样本与裁剪能力 | 原图或来源对象投影、共享裁剪结果、坐标往返 |
| CVAT 适配 | 类型化标签配置、当前步骤标注交换、对象身份与 frame 关联 |
| 平台服务和页面 | 按定义派生步骤进度、资格及锁定范围，协调现有操作 |
| 缓存与训练适配 | 调用定义选定的转换和训练能力，消费已发布输入，投影指标与交付产物 |

这些是现有组件的职责调整，不增加独立服务。通用模块提供原图、裁剪、坐标变换、标注交换和训练转换接口；Point 的 line 转 mask 等业务算法由 Point 模块拥有。新任务可以添加新算法模块，不要求把所有可能的几何转换预先实现。

## Point rules

| 步骤 | 输入与父对象 | 标注要求 | 开放和训练条件 |
|---|---|---|---|
| 检测 | 原图，无父对象 | 检测框，或人工确认的图片级有效负样本 | 有有效图片即可标注；全部图片已标注且至少 50 张有框原图才可训练并开放两个下游 |
| 分类 | 检测框裁剪，父对象为检测框 UUID | 每个裁剪图恰好一个类别 | 检测条件满足即可标注；自身全部裁剪图有标注即可训练 |
| 指针分割 | 检测框裁剪，父对象为检测框 UUID | 每个裁剪图至少一条两点 line，允许多条 | 与分类并行开放；自身全部裁剪图有标注即可训练 |

分类和分割互不消费对方标签。下游不另设样本数量门槛，不支持负样本；检测负样本计入已标注原图，不计入 50 张有框门槛，不产生裁剪图。门槛只统计工作区，不要求存在基准库或推理模型。

检测交付优化后的 ONNX；分类交付优化后的 ONNX、labels.txt 和每类参考图；指针分割交付优化后的 ONNX。沿用仓库训练默认值及初始权重来源，不使用历史训练产物初始化。每步仅向普通用户展示任务定义选定的主要指标。

## Annotation facts and associations

任务定义是规则权威，SQLite 是标注事实权威。保留图片目录、三表存储、稳定标注 UUID、显式 step_key 和单个可空 parent_id。几何统一保存原图坐标的 JSON 数组，SQLite 只保存原始标注；只有生成训练缓存时才转 mask、YOLO 或分类目录等训练形式。

数据层依据注入的任务定义检查步骤、类型、标签、允许的父步骤、同图关系与无循环约束。parent_id 保存实际来源对象，不能由步骤序号、形状类型、坐标相等或文件名推断。检测接检测时两个矩形仍有独立步骤身份；真正多级链的父对象指向直接来源，不强制全部挂在第一步检测框下。

编辑样本生成时建立 frame 到原图、来源对象与实际坐标变换的关联，并保存在可丢弃 Job 运行映射中。回收使用该关联还原坐标与 parent_id，不反复做位置配对。CVAT 原生对象 ID 映射继续负责保留平台 UUID，与 frame 来源映射分工明确。来源失效后旧 Job 不得回写；映射丢失则从权威标签重建，不猜测来源。

各步骤使用隔离的 CVAT 标注目标，只能交换当前步骤标签。沿用类型化标签、分类 Tag annotation、检测负样本 Tag、指针 Standard 与保存返回能力；不新增 CVAT 原生源码修改或只读上游展示。

## Dependencies, invalidation and identity

统一解释任务定义中的直接依赖与传递依赖，供下游清除、输入指纹和训练编辑保护共用。父来源是实际数据依赖，额外标签依赖必须有真实消费依据。定义加载时拒绝未知引用与循环，不用排列位置补齐依赖。

普通 CVAT 编辑按原生 ID 和稳定 UUID 定位变化。几何或业务标签变化才构成标注修改；颜色、选中状态、对象排列等显示变化不触发清除。变化或删除的来源对象使相关后代失效，保留其他对象的标签；真正额外标签依赖的影响范围按同一来源关联解释，不退化为整图无差别清除。身份丢失的全量替换按删除和新增处理，不做模糊匹配。

Point 分类修改不得清除分割标签、作废分割 Job 或训练缓存、改变分割输入指纹，也不得把对应训练任务按钮变成重新提交入口；分割修改对分类同样独立。检测框变化影响该框的分类和分割，其他框的数据保留。事务更新、旧 Job 拒收和可重建运行产物之间继续保持已有一致性约束。

指纹依据目标真正消费的图片、标签及必要转换参数生成，不包含模型版本或无关步骤内容。模型未重新生成标签时，不因模型更新改变输入。裁剪复用仍由原图、框几何及实际裁剪参数确定，分类和分割共用相同裁剪结果。

用户、工作区、目标和输入指纹唯一关联既有训练运行；相同输入不提供重新训练入口。已发布训练输入及历史记录保持可访问，不能随工作区编辑覆盖。实施计划必须明确指纹规则变更的兼容处理及验证：保留旧记录和缓存，不自动重训，不丢失任务关联，也不把不同实际输入错误关联为同一运行。不得直接重写历史指纹来掩盖语义差异。

## Training protection and derived state

训练只锁定会影响该运行输入的步骤，包括训练目标自身及其依赖闭包：

| Point 活跃训练 | 禁止编辑 |
|---|---|
| 检测 | 检测 |
| 分类 | 检测、分类 |
| 指针分割 | 检测、指针分割 |

多个待处理、排队、训练中或执行事实不明的运行取锁定范围并集，不能只检查页面当前用户显示的任务。任何活跃运行存在时仍禁止上传，因为工作区图片集变化会影响输入。终态解锁按现有权威事实规则派生；取消请求不等同于已经停止。

保护同时作用于页面入口和服务端 CVAT 回收，阻止用户保留已打开的编辑页后提交影响在训输入的修改。与任何活跃运行无关的兄弟步骤允许进入、编辑、回收及提交训练。判断与写入继续使用现有串行协调，不引入持久锁状态或并行写体系。

遵循[状态设计规范](../../implemented/process/2026-09-18-state-design-rules.md)：状态、计数、资格和锁定每次从权威事实重新派生，不保存当前阶段、不做加减计数，不从按钮动作推测完成。训练执行继续使用持久期望动作和协调器；查询只读，不通过读取恢复入队。页面消费服务端动态步骤列表，不另存固定三个步骤及顺序判断。

## Related decisions

本提案实施后将部分替代以下规则；在实现前，各 implemented 记录仍描述当前代码，不提前改写其验收事实：

- [Point 分类与分割](../../implemented/feature/2026-09-16-point-classification-segmentation.md)：替代顺序开放、分类清除分割和分割依赖分类指纹；保留裁剪复用、原始 line、身份和编辑隔离。
- [SQLite 存储](../../implemented/architecture/2026-09-16-sqlite-annotation-storage.md)：落实由任务定义解释父关系与依赖；保留存储格式、事务、对象级清除及备份边界。
- [训练闭环](../../implemented/feature/2026-09-17-point-training-loop.md)与[权威状态协调](../../implemented/simplification/2026-09-18-authoritative-state-coordination.md)：替代整工作区标签锁和公共层 Point 限制；保留查询只读、期望动作、队列、取消、已发布输入保护及真实验收结论。
- [训练输入身份](../../implemented/simplification/2026-09-17-training-input-identity.md)：保留唯一运行语义，补充按真实依赖计算指纹及历史兼容要求。

[总体平台提案](../feature/2026-07-30-self-service-training-platform.md)继续拥有部署与后续产品范围。本提案不提前引入管理员、任务创建页面或多工作区产品流程。相关记录各有仍有效的职责，不归档或删除。

## Alternatives considered

**只修正 Point 分割依赖。** 能处理一个错误，但存储、页面、缓存和 worker 的独立硬编码仍会让新增任务重复修改公共实现，不能满足核心价值。

**流程顺序或独立前置配置。** 展示顺序不代表标签消费关系；另存一套前置规则会再次把 Point 并行分支串行化。资格直接从真实输入与完成规则派生。

**页面创建任务或通用工作流引擎。** 当前没有动态编程或非开发者编排需求，几何与训练算法也不能只靠表单表达。采用 Python 模块和配置入口，接受新增算法需要部署代码。

**整工作区锁或整图清除。** 会阻止不影响训练输入的工作，且丢弃无关人工标签。现有稳定对象身份足以支持按依赖和关联限定范围，无须新增标注版本系统。

## Acceptance criteria

- Point 检测条件满足后分类和分割同时开放；两者不要求对方完成或上游训练，自身完整即可分别排队。
- 分类与分割编辑互不影响标签、Job、指纹、缓存和当前训练任务关联；检测变化只影响关联后代，无变化回收保持幂等。
- 验证三种单运行锁、并发运行并集、未知执行事实、终态解除、上传保护，以及已打开 CVAT 页的服务端回收保护。
- 使用非 Point 标识的合成任务，通过真实公共存储、CVAT 适配、缓存、HTTP/页面和 worker 路径验证定义加载；既覆盖并行分支，也覆盖检测接检测及真正多级父链，不只测试定义对象。
- 新增测试任务仅添加定义及必要专用算法、配置，不修改公共代码中的任务或步骤分支；平台与 worker 的任务选择一致。
- 保持检测负样本、50 张门槛、分类唯一类别、多指针 line、原始几何、训练默认值、主要指标、交付内容和既有认证权限的回归。
- 对旧指纹运行和缓存验证历史读取、当前输入关联及提交幂等；不自动重训、不误关联、不删除用户数据或发布产物。
- 运行跨模块回归、独立 wheel 消费检查及必要真实 CVAT/ClearML 验收；部署操作另行授权。实施后同步更新架构与原决策的现行事实。

## Partial implementation

任务定义已拥有任务与步骤名称、标注策略、样本门槛，以及父来源和额外标签依赖的统一传递闭包。Point 的分类与指针分割均直接依赖检测来源，彼此没有标签依赖；检测步骤声明 50 张有框原图门槛。配置可以选择受信任的 Python `module:factory` 入口，未配置时保持 Point 默认值。

通用标注规则按步骤定义校验类型、标签、几何和数量，并把空标注视为未完成的合法部分状态。图片级负样本使用空业务标签和空几何，步骤策略中的负样本标签仅声明 CVAT 能力。投影、样本编码、平台与 worker 组合、持久层和页面仍使用既有路径，后续实施再迁移这些消费者；本记录保持 proposed 状态。

## Risks

任务定义过宽会演化成框架，过窄则把 Point 判断留在公共实现。以当前真实能力和非 Point 集成测试约束接口，不提前实现 OCR、旋转裁剪或任意多父关系。

指纹纠正可能改变现有运行的查找结果；兼容方案必须在替换算法前落入实施计划，不能以清空验收工作区代替。任务定义与部署代码不一致也会造成错误训练，平台与 worker 必须使用一致的选择入口和定义。

本记录保留跨组件权威、历史兼容及验证约束，单独设置 3000 词预算；预算不作为删减已确认规则的理由。
