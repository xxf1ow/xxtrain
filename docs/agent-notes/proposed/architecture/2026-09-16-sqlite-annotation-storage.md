# Agent Note: SQLite 权威标注存储与对象关联

Status: proposed

## Problem

Point 检测闭环已经交付，但后续分类、分割及检测串联需要明确的步骤归属和对象关联。LabelMe 的几何类型不能区分两个检测步骤，原图中的位置关系和框类别只能隐式表达部分业务含义。将这些推断分散到编辑、同步和训练流程，会增加歧义与重复处理。目标是在保持已验收检测闭环和使用体验的前提下，建立唯一标注权威及可直接查询的关联，不建设通用数据版本平台。

## Proposal

批准采用 SQLite 保存平台权威标注，原始图片独立存放。本文部分替代[平台部署与数据集存储](../feature/2026-09-14-platform-dataset-storage.md)和[平台总体提案](../feature/2026-07-30-self-service-training-platform.md)中的权威 LabelMe、直接编辑原文件、暂不建设 SQLite、整图清除下游及后续模型标注表达约定；部署、业务任务隔离、去重范围、已交付检测事实和未被替代的产品约束继续有效。SQLite 权威存储、检测运行路径和离线浏览器 fixture 已经实现；真实 CVAT 往返与浏览器现场验收仍待完成，因此本文保持 proposed。

本次只做存储迁移和必要的 CVAT 对象身份接入，保留图片上传、自动去重、检测编辑与返回、页面布局、门禁和检测训练缓存生成。分类、分割只作为数据表达和清除规则的测试对象，不开放其页面或完整流程。无旧数据迁移脚本、通用格式导入导出系统、管理员页面、基准库维护、模型推理、真实训练或 ClearML 接入。2026-09-16 已验收检测增量的测试图片与标注允许丢弃，但本设计提交不执行删除；真实存量数据保持不动，后续管理员阶段再接入。

## Implementation progress

三表 schema、图片及标注记录类型、短连接 SQLite repository 和 Point 步骤定义已经实现。repository 在一个事务内按写入后的完整记录集合校验步骤、标签、几何、父关联、同图关系、循环及负样本冲突；64 位 pHash 以八字节 BLOB 保存。对象级差异规划按稳定 UUID 区分无变化、修改、新增和删除，按目标锚点清除依赖步骤及其对象子树，并在没有现存下游记录时仍报告失效步骤。CVAT 映射按 Job、对象类型和服务端 ID 保存，绑定校验样本范围与同图关系；标注删除、更新、新增和映射写入在同一事务内提交，重复绑定幂等且改绑被拒绝。

`WorkspaceData`、平台服务和 HTTP 真实组件使用 `annotations.db` 作为工作区唯一标注权威。图片接纳登记不可变事实，数据库聚合摘要，输入指纹排除 UUID、CVAT ID 和显示附加字段，检测缓存从数据库导出临时 LabelMe。离线浏览器 fixture 通过正式图片接纳和 repository 写入合成数据库，receipt 记录样本及初始标注身份；检测缓存离线覆盖五种 Point 框标签到类别 0 的投影、显式负样本、图片级门槛及发布后路径。重复摘要和指纹读取只查询已登记数据库事实。CVAT 初始化响应或恢复读取建立原生对象映射后，服务先持久化映射再发布 Job；回收要求每个 shape 携带原生 ID，按稳定 UUID 规划对象级变化，并在数据库事务前清除受影响目标的全部历史 Job 引用及发布结果指纹。事务失败保留原标注和映射，数据库提交后重启可按已发布指纹继续使用当前 Job。真实 CVAT 往返和浏览器现场验收仍待完成。

## Storage and ownership

每个工作区使用 `images/` 和 `annotations.db`。SQLite 是图片登记与标注的权威来源，图片文件承载原始内容。接纳后的图片不直接编辑；尺寸和哈希在接纳时计算并保存。数据库位于主机本地，只由平台后端访问，不通过 NFS 让训练从机读写；从机消费导出的训练输入。完整备份与迁移包含数据库一致性备份和图片目录，不把复制数据库单文件等同于完整数据备份。

`WorkspaceData` 拥有图片接纳、SQL、事务和查询；业务任务定义声明步骤、标注要求、父子关系及依赖，不包含 SQL；平台服务协调读写和外部调用；CVAT 适配交换平台内存类型，不直接访问数据库；页面不判断标签关系。保持现有几何类型和转换核心，编辑接口只补充身份往返所需字段，不把第三方对象带入通用数据层。

训练缓存从 SQLite 导出可丢弃的临时 LabelMe 输入，复用 `materialize_detection_source`、Point 检测投影和现有缓存发布流程。这不是权威 JSON 双写，也不是标注历史快照。图片目录与数据库之外的裁剪图、Job 引用、训练缓存仍是运行产物，原始图片与标注不按目标模型拆成独立权威数据集。

## Minimal schema

三张表足以覆盖本次职责，不为不同几何形状分别建表或拆点记录。

| 表 | 内容 |
|---|---|
| `images` | `id` 使用完整文件 SHA-256；`relative_path`、`width`、`height`、`perceptual_hash` 保存图片事实 |
| `annotations` | 独立稳定 `id`、`image_id`、`step_key`、可空 `parent_id`、`kind`、可空 `label` 与可空 JSON `geometry` |
| `cvat_annotation_map` | 当前 Job、CVAT 对象类型及对象 ID 到平台标注 ID 的映射 |

检测框也使用 JSON 点数组，不增加 `x1/y1/x2/y2` 列；多边形、折线、关键点等几何由其类型对应的代码校验和解释。只把几何载荷放入 JSON，不把类别、步骤或关联藏进去。分类是没有几何的独立标签，关联来源检测框，不占用检测框类别。显式检测负样本作为无几何标注事实保存，不将空图自动解释为负样本，且不能与该图的有效检测框同时作为互相矛盾的事实。

`step_key` 是业务任务声明的步骤标识，不是模型类型、权重版本或父链深度。数据层校验步骤存在、标注类型允许、父对象属于同图、关系无循环及父子步骤组合符合任务定义。每条标注至多一个父对象，不预建任意多对多对象图。检测框 A 可以同时拥有步骤二分类 B 和步骤三分割 C；B、C 的父对象都是 A，不能要求步骤号等于父链深度。检测接检测时，两个矩形分别具有自己的步骤归属。

SHA-256 用于身份及严格重复判定；pHash 用于视觉相似判定，不能当唯一身份。沿用 OpenCV 灰度、32×32 缩放、DCT 低频 8×8 和 64 位编码，当前相似阈值仍为汉明距离不大于 2。保存 pHash 避免重复解码已有图片，不改变候选排序、既有图片优先、过滤后不可找回或用户不可调阈值的规则。64 位 pHash 的落库表示必须无损，不能假设它总能装入 SQLite 有符号整数。本次不扩大到基准库相似过滤；基准库接入仍以 SHA-256 严格去重为既定方向，跨基准 pHash 比较只是后置可选议题。

## State derivation and admission

每次读取或用户动作完成后，从当前数据库事实与运行产物重新计算各步骤是否完整、页面计数和按钮条件。不持久化当前业务阶段、标签有效状态、图片计数或加减计数，不以数据库索引代替权威数据。显式负样本和步骤归属是标注事实，不是流程状态。状态按步骤依赖顺序计算，不从用户动作推测；写操作继续使用现有串行协调，操作期间拒绝并发变更。

保留检测有效图片大于零可标注、所有图片完成标注且至少 50 张有框图片才可生成缓存的规则。负样本计入已标注图片数并生成空 YOLO 标签，但不计入 50 张；所有门禁只统计工作区。缓存输入由图片和实际标签内容决定，不因管理员模型版本变化而改变；重复上传、相同内容回收、打开标注和生成缓存保持现有幂等语义，完成 Job 的重建规则不因存储选型而改变。

新工作区初始化图片目录和数据库。接纳先完成解码、去重和图片落盘，再提交图片记录；SQLite 不与文件系统共享事务。失败留下的未登记图片不参与业务查询，也不被自动接纳。不建设目录监听、自动扫描修复或旧工作区迁移；重启从数据库恢复，而不是重建文件索引。SQL 事务失败必须回滚，错误经现有平台接口反馈，不显示部分成功的计数。

## CVAT identity and synchronization

平台标注 ID 独立于 CVAT ID。CVAT shape、tag 等对象必须连同类型和 Job 定位，不能假设 ID 跨类型、重建或全量覆盖仍稳定。初始化 Job 时由适配层接收服务端对象身份并建立映射，新增对象回收时分配平台 ID；映射建立必须有可验证的对应依据，不靠模糊坐标匹配。重建 Job 重新建立映射，但保留其输入标注的平台 ID。映射是可重建的编辑关联，不是第二份标签权威。

一次回收以平台内存中的几何及业务标签判断变化，排除界面颜色、选中状态等显示信息；不比较原始响应字节，不将标注排列顺序变化解释为修改。

| 回收结果 | 原子更新 |
|---|---|
| 已知 ID 且内容未变 | 保留平台 ID、标注与下游 |
| 已知 ID 且几何或业务标签变化 | 更新该标注，清除对应目标受影响的下游 |
| 已知 ID 消失 | 删除该标注及受影响的下游 |
| 新 ID | 创建新标注并登记映射 |
| 全量替换导致身份丢失 | 按旧对象删除、新对象新增处理，不推测对应关系 |

下游范围同时依据步骤依赖和目标关联确定，不能只靠 `parent_id` 的删除级联。分类 B 与分割 C 都关联检测框 A 时，改变 B 仍可按任务规则清除 A 的 C；框 D 对应的下游不得受影响。几何约束及标签依赖由任务定义解释，数据库不硬编码 Point 的模型类型或步骤编号。

标注修改、下游清除及新增映射在同一 SQLite 事务中提交。上游变化使相关下游 Job 过时时，旧 Job 不得回写；下次进入重建 Job，带入仍然保留的其他目标标签。此过程不存历史标注或追踪历史版本。Job 引用与输入指纹仍由运行缓存管理，重启、同步重试和事务失败时不得让运行缓存绕过旧结果拒收规则。

### Source inspection evidence

2026-09-16 只读检查了验收机 `/home/lxx/xxtest/services/cvat/` 的源码，未启动服务。`cvat-core/src/annotations-saver.ts` 的 `_split` 按原 ID 区分更新、删除和新增，常规保存保留原 ID；`save` 的 `flush` 分支移除服务器 ID 后全量 PUT。`annotations-collection.ts` 的全量 `clear` 设置 `flush`。后端 `cvat/apps/dataset_manager/task.py` 的 `update` 使用输入 ID 删除并重建对象，`put` 执行全量替换。现有平台 `client.py` 丢弃初始化 PUT 的对象响应，`codec.py` 未读取 shape ID，因此需补充适配，不能把 CVAT 原生能力视为平台已经实现。源码检查仅支持可行性判断，初始化映射、复制新增、普通编辑、全量替换和重试仍需真实 API 往返验证。

## Deferred model and baseline workflow

交付顺序是本次存储迁移、分类闭环、分割闭环，Point 三模型稳定后才建设已有标注上传、管理员审核与并入基准库的产品流程。不因数据库迁移提前加入角色体系或管理页面。基准库与模型仍仅管理员管理；没有基准库或预训练模型不阻塞工作区推进。

后续分类与分割采用第一步检测框的临时裁剪图编辑，只展示当前目标。分类给裁剪图选择类别，分割在裁剪图上标注；结果写入同一权威数据库，几何转换回原图坐标。临时映射记录来源对象和实际几何变换，不在权威标注中保存临时图片路径。旋转裁剪未作为本次需求确认，不预建旋转编辑功能。后续训练仍按用户选择的目标独立执行，不要求先训练前置模型才能进入下一步标注。

存量 LabelMe 的框类别承载分类、空间匹配分割等语义留在业务任务导入适配器中；后续导入时转换为显式关系，不在常规编辑期间反复推断。导入工作区的数据可先持久化，再通过 CVAT 审核和修正，管理员之后纳入基准库；写入 SQLite 不等于审核通过。普通 LabelMe 工具不直接编辑权威数据。按模型导出时仍可能依赖上游框生成裁剪，不能只筛选当前步骤的记录就宣称得到完整训练集。本次临时检测导出之外的通用交换格式能力后置。

## Alternatives considered

**保持原生 LabelMe 并持续空间推断。** 几何类型无法区分检测串联，位置关系可能歧义，不能提供明确的对象身份及事务更新。

**扩展 LabelMe 元数据或把整份 LabelMe 放入 SQLite。** 两者都能表达自定义关系，但前者需自行维护跨文件引用与一致更新，外部编辑器不保证保留关系；后者仍将关系隐藏在文档中。数据库用于关系存储而非 JSON 文件索引。

**所有几何完全拆表或为框增加数值列。** 当前主要整对象读取、编辑和转换，不在 SQL 中逐点分析；统一 JSON 几何减少特殊表和数组组装。此选择不承诺 JSON 比点表更快。

**PostgreSQL。** 原生数组、多写者能力不抵消当前单主机后端的服务、账号及运维成本。SQLite 索引查询可能改善统计和关联延迟，但不加速 CVAT 网络、裁剪或训练，也没有已测量的性能倍数承诺。

**永久整图清除下游或模糊匹配修改后的框。** 已核查的 CVAT 普通编辑 ID 允许直接定位对象，框级清除能保留未受影响的人工劳动；身份丢失按删除新增处理，不以复杂匹配维护猜测关系。

**先建设存量导入和管理员归档，再支持分类分割。** 数据治理不是工作区多模型闭环的依赖，会提前扩大页面和权限范围。存量兼容后置但不删除真实历史数据，也不为无价值验收数据建设迁移工具。

## Acceptance criteria

- 新工作区的真实 HTTP 上传、去重、CVAT 检测编辑与返回、计数刷新、至少 50 张有框图片的缓存生成保持现有体验；分类分割按钮仍禁用，真实训练未启动。
- SQLite 是唯一标注权威；训练临时 LabelMe 与最终 YOLO 输入在图片、标签、负样本和发布路径语义上符合现有检测规则。未登记图片不进入状态和训练。
- 所有几何统一 JSON 存储；步骤、父关联、类别可独立查询；检测接检测、检测接分类及分割关系通过数据层样例验证，错误步骤、跨图父关联和循环被拒绝。
- 重复回收不改变平台 ID、不清除下游；修改和删除某个框只影响对应目标，分类与分割同父时仍按依赖正确清除；无业务变化的显示操作不触发清除。
- 新增映射与标注写入原子提交，注入事务失败不留下半套更新，重试不重复创建标注；进程重启后仍能使用已登记映射。
- 真实 CVAT 往返验证初始化映射、移动、改类、新增、删除、复制与全量替换；旧下游 Job 不得回写，重建保留未受影响标签。源码核查不替代此项验收。
- 不新增迁移脚本、管理员、基准库管理、推理或历史版本；真实存量文件保持不变。实现期间按实际改动更新架构、开发及测试文档。

## Risks

数据库文件与原图不能原子提交；未登记残留被忽略但不会自动恢复。数据库备份必须一致，图片也须纳入备份。SQLite 的并发写限制由现有单进程短事务协调承担，不因为引入数据库增加后台调度系统。

CVAT ID 只在受支持的编辑生命周期内稳定；初始化响应的对应关系、坐标数值往返和全量替换必须通过测试，不能误删未修改对象的下游。平台不保证全量导入替换后还能保留旧对象身份。旧 Job 拒收与缓存重建涉及跨系统时序，必须验证失败及重启路径。

单父标注关系覆盖当前目标归属，不宣称能够表达任意多父关系或车道拓扑。新增业务要求超出该范围时需独立设计；不为假设需求增加表。几何 JSON 仍有解析成本，采用 SQLite 的主要依据是显式关系与一致更新，而不是未经测量的性能收益。
